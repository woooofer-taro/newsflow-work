ローコードAPI管理ツール、複雑さに立ち向かうが注意点も

Low-code API management tool fights complexity, with caveats
TechTarget2026-11-03 21:00報道

API管理は複雑すぎることが多いと専門家の意見は一致している。しかし、ローコードの代替手段を提供しようとする新興企業の最近の取り組みは、まだ普及へ向けて険しい道のりに直面している。

ビジュアルAPIツールは、APIコード生成やAPIテストなど、API管理の特定の側面に対処するものとして、数十年前から存在している。たとえば、Swaggerは API の設計とドキュメント作成を支援し、Twilioは API のやり取りがどのように行われるかを可視化できる。API管理分野で競合する他のツールには、Postman、APIMan、F5 Nginxがある。

今回、新たな競合としてAPIwizが登場した。2017年に設立された同社は、3月に200万ドルのシード資金調達ラウンドを実施した。このスタートアップは、ローコードのビジュアルインターフェースを拡張してAPI管理のライフサイクル全体を網羅し、プロの開発者の枠を超えて誰でも利用できるようにすることを目指している。

「今日のAPIライフサイクル全体は、さまざまなツールや技術によって細分化され、それぞれが対処している。[……]設計に重点を置くものもあれば、CI/CDの自動化、サンドボックスの作成、[または]開発者ポータルの構築に重点を置くものもある」と、APIwizの共同創業者兼CEOであるRakshith Rao氏は述べた。「APIwizは、『API管理ライフサイクルのさまざまな側面を、どのようにして単一のペイン・オブ・グラスの下にまとめるか』というアプローチを取っている」

Rao氏によると、このプラットフォームはプロの開発者にビジュアルツールを提供することに加え、JSONやYAMLといったインフラのコード化言語などの従来のプログラミング言語を理解しなくても、市民開発者がAPIを構築、公開、保守できるようにするという。

APIインフラの構成に対するローコードのアプローチにより、開発者は新しい構文を学ぶことなく構成ファイルを構築できる可能性があり、製品マネージャーのような非開発者や、技術的な知識はあるもののコードに抵抗がある人々にも、API構成の道を開く可能性がある、とカリフォルニア州コンコードを拠点とするフリーランスのテクニカルコンサルタント、Rob Zazueta氏は語った。

「正直なところ、複雑な技術的要素をより多くの人にとって身近なものにすることで、デジタル空間を民主化するものには賛成だ」と彼は述べた。「APIwizは、ある意味では少しうまい話すぎるように聞こえる。しかし、API管理と構成は現在、一部のチームにとって管理するには難しすぎるという議論も成り立つと思う」

ノーコード/ローコードのAPI管理プラットフォームを利用することのもう一つの潜在的な利点は、スピードである。APIwizのユーザーインターフェースにアイコンとして用意された事前構築済みのモジュールにより、構成ファイルやその他のコンポーネントを手作業でコーディングする必要がなくなり、作業時間とミスが減るとRao氏は述べた。

ローコードは一括構成も高速化できる、とZazueta氏は述べた。

「[API管理]ツールの従来の[ユーザーエクスペリエンス]は多少制限的で、一括構成を行うのが難しかった」と彼は述べた。「数十のエンドポイントを新しい管理システムに移行したい場合、インターフェースの数十のフォームを順番にたどる必要があったかもしれない」

ローコードAPI管理と懐疑派

手作業でのコーディングに代わるもう一つのAPI管理の方法は、Open API仕様などの形式を使って、すべてのAPIエンドポイントをYAMLまたはJSONファイルに追加することである。しかし、これは技術者でないユーザーにとっては依然として負担が大きい可能性がある。

「YAMLやJSONであっても、それはコードだ。そしてそれは威圧的に感じられるかもしれない」とZazueta氏は述べた。「つまり、管理のための選択肢は、フォームのページをたどるか、開発者にさらにコードを書いてもらうかのどちらかだった」

APIwizのRao氏は、同社の製品はこうした課題を回避し、開発チームの誰もがAPIの作成、公開、保守を行えるようにすると主張している。これには、市民開発者、専門分野の専門家、製品マネージャーが含まれる。

Rao氏によると、こうした非コーダーは、APIの管理チームが多くのリクエストに追われている場合に、しばしば起こることだが、支援できるという。テストケース、スクリプト、ドキュメントの作成といった地味な作業を担うことができ、それが全員の作業を速める。

しかし、より複雑なAPI構成へのアクセスを必要とする非コーダーが何人いるのかは明確ではない、とZazueta氏は述べた。

「確かに一部はいるだろう。しかし、大部分がOpen APIの仕様ファイルで管理できて、非コーディングのチームが特定の顧客層向けにエンドポイントをまとめたり、ポータルを管理したりすることに主に注力しているのであれば、このローコードのアプローチは過剰かもしれない」

APIwizは、ある意味では少しうまい話すぎるように聞こえる。しかし、API管理と構成は現在、一部のチームにとって管理するには難しすぎるという議論も成り立つと思う。

Rob Zazueta

フリーランスのテクニカルコンサルタント

別の開発者は、ローコードプラットフォームがAPI管理の全範囲をカバーできるのかという疑問を呈した。

「私の経験から言えば、ローコード/ノーコードツールは80/20の法則に従う」と、ケンタッキー州ルイビルのRepublic Bankでアプリケーション開発マネージャーを務めるAdam Stivers氏は述べた。「これらは約80%のユースケースをカバーする。しかし残りの20%は複雑すぎるか、独特すぎて扱えない」

ビジネスが成長し拡大するにつれて、より複雑なケースが生じ、より多くの構成やコーディングが必要になり、問題を全体的に見るためにプロの開発者が必要になる、とStivers氏は述べた。ローコード/ノーコードツールは、そうしたケースで開発者が創造的な解決策を見つけることを妨げることが多い、と同氏は言う。

APIwizは使いやすそうに見えるが、一般的な市民開発者がこのプラットフォームを使って、APIのライフサイクル全体を端から端まで管理できるかは疑わしい、とForrester Researchのアナリスト、David Mooter氏は述べた。

たとえば、APIには通常、RESTプロトコル（サービス接続の一連の慣習）の理解や、APIを保護するための相互TLSやOAuthといったセキュリティの概念の理解が必要である。さまざまなプライバシー規制に準拠する方法を理解することも重要だ、とMooter氏は述べた。

「APIの設計ツールがどれほど簡単であっても、それらの概念の理解の必要性をなくすことはできない。そして、ほとんどの市民開発者はそうした分野のバックグラウンドを持っていない」とMooter氏は述べた。「APIをどう保護するかについて市民開発者が誤った判断を下すことは、最も避けたいことだ。プロのコーダーでさえ、すでにAPIセキュリティで十分な間違いを犯している。そして彼らは、市民開発者よりもはるかにセキュリティに精通している」

しかしRao氏は、APIwizは実際には、セキュリティを含むこれらの概念の詳細のほとんどを理解する必要を市民開発者からなくすと反論した。それらのルールは、企業のセキュリティチームが製品内で事前に定義できるという。市民開発者はRESTについてある程度の知識を持つ必要があるが、それは数時間のトレーニングで身につけられる、と同氏は述べた。

複雑なユースケースについては、APIwizは、チームが数万件のAPIを管理する、シンプルなものから複雑なものまで、あらゆるユースケースに対応できるとRao氏は述べた。

APIwizの無料プランは、APIの設計と共有を行いたい個人を対象としている。複数の製品チームを抱える企業向けのチームレベルは、ユーザーあたり月額249ドルである。これにはAPIテスト、仮想化、監視が含まれる。より大規模な企業向けには、個別見積もりが提供されている。
