ファイアウォールが足がかりに：攻撃者がCheck Pointのゲートウェイを顧客に対する攻撃に利用

The firewall becomes the foothold: Attackers turn Check Point gateways against customers
Network World2026-11-14 13:00報道

攻撃者が新たに開示された権限昇格の脆弱性を PHP2Shell と連鎖させ、ゲートウェイを乗っ取り、ネットワーク構成を盗み、破壊的マルウェアを展開した。

ファイアウォールは、攻撃者が越えられない境界であることを意図されている。

しかし、ファイアウォールはウェブに面しているため、他のシステムと同様に攻撃を受けやすい。Check Point Software が自社の複数の製品向けに緊急ホットフィックスを公開したことが、それを示している。これらのパッチは、深刻度の高い権限昇格の欠陥 CVE-2026-123039 に対処するものだ。この欠陥により、攻撃者は root 権限でのアクセスと、中核のバックグラウンドプロセスである Gaia OS Dynamic CLI デーモンへコマンドを送る能力を得る。

ハッカーは 10 月下旬から、この評価 7.8 の脆弱性を悪用しており、Check Point は「数十社」の顧客が影響を受けたと述べた。

おそらく驚くことではないが、攻撃者は PHP2Shell を介して初期アクセスを得た。PHP2Shell は、CVE-2026-109618 と CVE-2026-109619 として追跡されている 2 つの重大な PHP の欠陥の総称である。深刻度 9.2 と評価されたこれらのバグは、認証なしのリモートコード実行（RCE）を可能にする。

「顧客にとっては、1 つの足がかりでフルコースが提供された。スパイ、居座り、破壊だ」と Dickson Research の Frank Dickson は述べた。「Check Point にとって、代償は信頼だ。ファイアウォールはネットワークで最も強い地点であるはずで、最も弱い地点であってはならない」

意図しない root アクセスの付与

CVE-2026-123039 は、Dynamic CLI IPC（プロセス間通信）インターフェースのバグであり、このインターフェースは特権コマンドの要求を root レベルの Gaia OS Dynamic CLI に送る。これはローカル権限昇格の欠陥であり、攻撃者がすでにアプライアンス上でローカルコード実行能力を持っている必要があることを意味する。これが評価 7.8 の理由である。

攻撃者はまず、PHP2Shell の脆弱性を悪用して Mobile Access ポータルへのアクセスを得た。その後、CVE-2026-123039 のゼロデイエクスプロイトを使って権限を root に昇格させた。

「攻撃者が root を得れば、好きなものを何でも実行できる」と Dickson は述べた。アプライアンス上の管理サービスは root として動作し、ボックス上のどのプロセスでも書き込めるローカルソケットで待ち受け、呼び出し元が誰かを一切確認しない。

今回のケースでは、攻撃者はポータルがログインページの構築に使うテンプレートの内部に web シェルを隠し、再起動後も残り、バックアップやスナップショットに潜り込み、アプライアンス自身のプロセス内に隠れる TSGA バックドアと TSProxy マルウェアをインストールしたと、彼は説明した。

「そのバックドアはファイアウォールの構成をコピーでき、それは本質的にネットワークの設計図だ」と彼は述べた。また、ファイアウォールのログを改変して、攻撃者の活動を隠すこともできる。

Check Point は、root アクセスを得た後、攻撃者が侵害したゲートウェイから SSH で VMware ESXi ホストへ移動し、destroy_v6 ワイパーを展開し、破壊の段階で Dream Security Ltd と名乗るグループの署名入りの政治的なテーマのメッセージを残したと報告した。

Check Point はセキュリティチームに対し、Mobile Access をインターネットに公開しているデバイスから始めて、CVE-2026-123039 のホットフィックスを直ちに適用するよう助言した。すぐに適用できない場合は、*dynamic_server* プロセスを停止し、再起動を防ぐべきだとしている。ただし、これには一部の CLI コマンドが使えなくなる代償が伴い得ると警告した。

Dickson はさらに、顧客に対して、使っていない Mobile Access を無効にすること、管理インターフェースを完全にインターネットから外しておくこと、10 月下旬以降に公開されていたあらゆるゲートウェイでアドバイザリのログ確認を実行すること、そのうえでファイアウォールとハイパーバイザーの間の接続を切ることを助言した。侵害の可能性があるゲートウェイが VMware ESXi への信頼された経路を持つべきではない。

また、ファイアウォールのログを、発生と同時に、ファイアウォールが触れられないシステムへボックスの外に送るべきである。

CVE-2026-123039 の影響を受ける製品には、Check Point の Firewall、Multi-Domain Security Management Server、Security Gateway、Security Management Server、Scalable Platforms が含まれる。

セキュリティツールは、守る対象と同じくらい大きな標的である

攻撃者が root アクセスを得ると、そのデバイスは基本的に、本来なら保護されたままのはずの他のシステムに対する攻撃の、信頼された足場となると、Infotech の技術顧問 Erik Avakian は説明した。ゲートウェイを事実上制御することで、攻撃者は幅広い悪意ある行為を実行できる。

Avakian は、これの全体的な教訓であり皮肉は、組織が自らを守るために導入する技術そのものが、最大の脆弱性の 1 つになり得ることだと指摘した。

「組織はもはや、セキュリティインフラが保護を提供するよう設計されているというだけで、本質的に安全だと考えることはできない」と彼は述べた。実際には、それは守っているシステムと同じくらい標的なのである。

ファイアウォール、VPN アプライアンス、セキュリティゲートウェイは、最大のてこ入れと制御を提供するため、ますます標的にされていると彼は指摘した。そのためセキュリティチームは、これらのアプライアンスを高価値の資産として扱い、他の重要インフラに適用されるのと同じアクセス制御の保護策、脆弱性管理、監視、インシデント対応の厳格さを適用しなければならない。

これは、インターネットに面したシステムに積極的にパッチを適用し、管理アクセスを制限し、異常な管理活動を監視し、永続化や横方向の移動の兆候を探すことを意味すると、彼は述べた。しかし、パッチはすでに定着した攻撃者を追い出さないため、セキュリティチームは調査し、必要に応じて、影響を受けたシステムを信頼できるイメージから再構築しなければならない。

また、AI が攻撃を加速させるなか、CISO は、アイデンティティ、ネットワーク、アプリケーション、データ、デバイスの各柱にわたって、ゼロトラストの考え方とアーキテクチャを全体として確立することを検討すべきだと、彼は述べた。

エッジに目を光らせる

エッジデバイスは、境界に位置し、特権アクセスを持ち、他のシステムのようなエンドポイント監視をほとんど受けないため、主要な標的であると、DataBee の CTO である Scott Miserendino は指摘した。セキュリティアプライアンスは、それらがなってしまった高リスクの資産として扱われるべきである。

パッチの適用と緩和策の適用に加えて、防御側は侵害があったと想定し、公開されている侵害指標（IOC）を探し、ネットワークとエンドポイントのセキュリティログを定期的に調査し、被害範囲を減らすためにネットワークを分割すべきだと、彼は助言した。「セキュリティツールは自動的に安全なわけではない。だから防御者を守れ」と彼は述べた。

そして Dickson は、PHP2Shell は、PHP が多くのウェブソフトウェア、セキュリティアプライアンスに取り付けられたポータルを含め、その基盤にあるため、今後も現れ続けるだろうと指摘した。したがって、常に防御側のレーダー上にあるべきである。

管理プレーンは主要な標的である

Check Point は、脅威アクターの被害者として孤立しているわけではない。ファイアウォールの管理は、業界全体で攻撃者の好む標的になっている。

たとえば 1 月に、Fortinet は、攻撃者が FortiCloud のシングルサインオンを悪用して、他の顧客の FortiGate および FortiManager デバイスにログインし、管理者アカウントを作成したことを開示した。7 月と 9 月には、CISA が Check Point の管理サーバーの欠陥を、悪用された脆弱性のカタログに追加した。

同じ月に、同機関は、認証なしの攻撃者に root アクセスを与える、深刻度が満点の 10.0 と評価された Cisco Secure Firewall Management Center の欠陥も追加した。そして 10 月に、Palo Alto Networks は、再び「ファイアウォールの root が賞品」として、PAN-OS 管理インターフェースへの攻撃について警告した。

「論理は単純だ」と Dickson は述べた。「管理プレーンは、ネットワーク全体のルールブックを保持している。

欠陥の少ないプロバイダーに乗り換えることは選択肢の 1 つだが、ベンダーを替えても 1 つのアキレス腱を別のものに替えるだけだと、彼は指摘した。どのベンダーのエッジデバイスにもウェブポータルがあり、すべてのウェブポータルは扉だからだ。「解決策は、扉を減らすことだ」と彼は助言した。「インターネットに面したエッジを縮小し、リモートアクセスを 1 つの一貫したアイデンティティポリシーの背後に置け」

結局のところ、ファイアウォールは壁ではなく、インターネット上にあるコンピュータなのだと、彼は述べた。「攻撃者はそれをそのように扱っている」と彼は述べた。「セキュリティチームも、そのように守るべきだ」
