サンドボックスを超えて：Ciscoの幹部が多層的なAIセキュリティを促す

Beyond the sandbox: Cisco leader urges AI security in depth
TechTarget2026-11-13 07:00報道

ソルトレイクシティ発 – Cisco Isovalent のオープンソース責任者は、クラウドネイティブインフラストラクチャの10年にわたる発展、ネットワーキングとセキュリティの融合を含め、その最前列で見てきた。

これらすべての分野の交差点に位置するのが Isovalent であり、同社は拡張 Berkeley Packet Filter（eBPF）Linux カーネルユーティリティに基づくネットワーク監視・セキュリティのオープンソースプロジェクトである Cilium と Tetragon の管理者である。Isovalent は2023年後半に Cisco に買収され、その後、Linux 上で動作する Cisco のスイッチング機器に組み込まれている。Cilium は eBPF を使用して、Kubernetes クラスター内で軽量なサービスメッシュによりトラフィックをオーケストレーションし、Tetragon はアプリケーションのランタイム可観測性とポリシー適用を行う。

Isovalent の chief open source officer である Liz Rice は、今週ここで開催されている KubeCon で話題になっている microVM ベースのエージェントサンドボックスではなく、コンテナベースのランタイムセキュリティに明らかに利害関係を持っている。しかし彼女は、microVM の利点は、彼女が運営委員会に名を連ねる Cloud Native Computing Foundation（CNCF）コミュニティ内でまだ議論中であると指摘した。

「サンドボックスの観点で何が必要かについて、多くの議論が見られる……その多くは進行中の作業だ。……今や、エージェントにとって適切な分離境界は何かという、ほとんど哲学的な話になっている」と、彼女は今週ここで IT Ops Query ポッドキャストのインタビューに応じた際に述べた。

MicroVM とコンテナ分離の議論

従来の VM より軽量でありながら OS レベルの分離を保持する microVM の支持者は、コンテナの性能と効率と、VM を取り巻くより強固な境界との間でバランスを取っている。Google の gVisor や Kata containers を含む microVM は、Nvidia と Google が CNCF に寄贈したエージェントサンドボックスプロジェクトと統合される。今週の Broadcom と SUSE によるオープンソースコミュニティでの他のアップデートも、これまで分かれていた VM 管理とコンテナ管理の領域の境界を曖昧にした。

Isovalent の Tetragon もインフラストラクチャベースのポリシー適用を提供するが、VM ではなくコンテナを使用しており、Rice はこれがエージェント型インフラストラクチャが必要とする大規模でワイヤースピードのネットワーク運用により適していると述べた。

「これらの microVM には多くの可能性があり、たとえば5年前、VM の起動に少なくとも何秒も何秒も何秒もかかっていた頃と比較すると興味深い。今の microVM ではずっと速い」と彼女は述べた。「しかし、可観測性などに関して異なる緊張関係が生じる……そして、性能は通常のコンテナランタイムで得られるものと全く同じではない」

microVM はより強固な分離を提供する一方で、コンテナと比べて実行中のワークロードへの可視性を不明瞭にすることもある、と Rice は述べた。悪意のある、または意図からずれた AI エージェントを封じ込めるための予防措置には限界があり、不審な動作が起きたとき（起きるかどうかではなく、いつ起きるかの問題である）、迅速に捉えるには深く迅速な可視性が不可欠である。

ある意味でこれは二者択一の議論ではない。ほとんどの企業は多層のセキュリティを追求することになり、これは多層防御として知られる実践である。しかし、エージェントが要求する規模と性能と、それらを安全に実行することとの間のバランスを取ることは、Rice によれば引き続き重要である。

たとえば、Tetragon は6月に提供開始された Cisco の Live Protect 仮想パッチ機能を支えている。この機能は、新たに発見されたソフトウェア脆弱性を使った攻撃から Cisco のスマートスイッチを、それらの脆弱性がアップストリームでパッチされるより速く保護できる。

「私たちはランタイムセキュリティ保護と緩和策を持たなければならない。パッチを展開する時間的余裕がないからだ。起こりうるすべての攻撃を予測することはできない」と Rice は述べた。「理論上は長い間可能だったが、通常の運用に影響を与えることへの懸念が常にあった。しかし、脆弱性の猛攻により、リスクのバランスが変わりつつあり、人々がそうしたガードレールを設けることがますます理にかなってきている」
