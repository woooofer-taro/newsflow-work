PHP2Shell攻撃がPalo Altoファイアウォールのroot権限を奪取、ただしWordPressには通用せず

PHP2Shell Attacks Root Palo Alto Firewalls but Fail Against WordPress
SecurityWeek2026-11-05 07:00報道

PHP2Shell を悪用する攻撃者が1週間以上にわたりサーバーを叩き続けているが、これまでに確認された侵害成功はごくわずかである。

目立つのは Palo Alto Networks のファイアウォールで、PHP2Shell と Fragnesia カーネル権限昇格バグを連鎖させた攻撃により、中国と関連のあるハッキンググループに root 権限を奪われている。

AI の支援を受けたハッカーは2つの別個のエクスプロイトを連鎖させた。1つは Palo Alto Networks の PAN-OS デバイス上の PHP2Shell の脆弱性 CVE-2026-109618 と CVE-2026-109619 を特に標的とするもので、もう1つは root 権限で Web シェルを展開するための Fragnesia 用のものである。

サイバーセキュリティ企業の Dream は今週初めにこのキャンペーンを指摘し、数百台の中から少なくとも25台のファイアウォールが侵害されたと述べた。Palo Alto Networks はその後、この調査結果を確認した。

「Dream Research は、攻撃者が PHP2Shell を Linux カーネルの権限昇格の脆弱性と連鎖させて root アクセスを得たキャンペーンを報告した。Unit 42 は同じ攻撃者のツールを独自に検証し、報告された結果を確認した」と Palo Alto Networks は述べた。

同社は、PA-Series および VM-Series ファイアウォール、ならびに Panorama（仮想および M-Series）向けの PAN-OS 12.2、12.1、11.2、11.1、10.2 において、PHP2Shell の脆弱性を解決するパッチを公開した。

「この問題の影響を受けるために特別な設定は必要ない。インターネットに公開された Palo Alto Networks の管理インターフェースを標的とする悪用が確認されている」と同社はアドバイザリで述べている。

Palo Alto Networks は、デフォルトでは管理インターフェースはインターネットに公開されていないとし、顧客に対し、直ちにそのアクセスを制限し、利用可能な修正を適用するよう促している。

「インターネットに面した管理インターフェースが設定され、影響を受けたのは、当社のグローバルな導入基盤のごく一部（約0.02%）にすぎない。これらの顧客にはそれぞれ当社チームが個別に連絡を取った。当社は引き続き調査し、必要な更新があれば入手でき次第提供する」と Palo Alto Networks は述べている。

公開されている2260万の PHP インスタンス

同社によると、10月29日時点で、同社のテレメトリは PHP2Shell のバグに対して脆弱である可能性のある、公開された PHP インスタンスを2260万以上特定している。

PHP は、WordPress、Drupal、Joomla などをはじめ、サーバーやコンテンツ管理システム全体で広く使われていることを考えれば、これは驚くべきことではない。

大規模な PHP2Shell の悪用はこれらも標的にしているが、少なくとも WordPress に関しては、ほとんど成功していないと、Web セキュリティ企業の Defiant は述べている。

10月28日時点で、Defiant は PHP2Shell の悪用によって侵害された WordPress サイトを把握していないが、2,000を超える IP アドレスからの関連リクエストを7万7,000件以上記録している。

ただし Defiant は、テストにより、標的のサーバー上で動作させるには、ASLR、PHP ビルド、実行中の拡張機能、メモリ制限、サーバーのリクエスト処理の影響を受けて、エクスプロイトの調整がしばしば必要になることが明らかになったと指摘している。

「攻撃者は依然としてツールを変更している。攻撃が成功すれば、サイトのファイル、データベース、パスワードにアクセスされる可能性があるため、PHP の更新は引き続き不可欠だ」と Defiant は警告した。

ひと握りの IP

PHP2Shell の悪用の試みは広範囲に及ぶものの、成功したのはごく少数の攻撃者によるものとされている。

Cato Networks によると、同社がブロックした攻撃の約96%が CVE-2026-109618 を標的としており、そのうち41%がリモートコード実行（RCE）を試みたもので、残りはスキャンまたは無効な PoC の試行だった。

これらの試行は、米国、オランダ、ドイツのひと握りの IP から発信されており、概念実証（PoC）形式のリクエストを繰り返していた。その大半はコマンド実行に焦点を当てており、次いでデシリアライゼーションの試行が続いた。

Cato によると、最も多く標的にされたのは医療機関で、次いでテクノロジーおよびセキュリティサービス、プロフェッショナルサービス、自動車、教育および非営利、製造・建設・小売の順だった。

ただし、攻撃は標的を絞ったものではなく、日和見的であるように見えた。同じ発信元が同じ日に医療、テクノロジー、ソフトウェア分野の組織にリクエストを送っているのが確認されたためである。

WatchTowr は、大量の試行と多様なペイロードにもかかわらず、ドイツの単一の IP アドレスからの PHP2Shell の悪用成功を確認したと述べている。

「あらゆるケースで、悪用が成功したことを示すために単純な 'curl' コマンドを実行し、そこで止まっており、追加の侵入後の活動はない」と、WatchTowr の脅威インテリジェンス責任者 Jake Knott は述べた。

「より信頼性の高いエクスプロイトが開発されるにつれ、新しい手法、独創的なペイロード、より優れたアプライアンス固有のエクスプロイトが飛び交っており、特定のエッジアプライアンスに対する高度に標的を絞った悪用成功の公的な報告は増え続ける一方だろう」と Knott は付け加えた。
