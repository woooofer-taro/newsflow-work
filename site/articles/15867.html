DXC OASISとCiscoがネットワークチームにAIによるインサイトを提供

DXC OASIS and Cisco Bring AI Insights to Network Teams
TechnoSports Media Group2026-11-21 21:00報道

DXC Technology は、企業のIT運用を調整するプラットフォームである DXC OASIS に、AIを活用したネットワークインサイトを取り込むため、Cisco と協業していると述べている。

発表された取り組みは、当初は Cisco Meraki 環境におけるワークプレイスの Wi-Fi パフォーマンスインシデント に焦点を当てる。その目的は、IT チームが問題を調査し、ネットワークツール、インフラストラクチャ、アプリケーション、サービス管理ワークフローをまたいで承認済みの対応を調整できるようにすることである。

2026年11月20日付の DXC の発表によると、このアプローチは、Cisco のネットワークインテリジェンスと、AIエージェント、運用上の専門知識、人間による監督を組み合わせたものである。リリースでは、価格、顧客への提供開始時期、このインテグレーションの一般提供日は明記されていない。

DXC と Cisco の協業：主な詳細

DXC OASIS とは何か？

DXC OASIS は、同社によって、企業のIT運用に向けて人間の専門知識とエージェント型AIを組み合わせるインテリジェントなオーケストレーションプラットフォームと説明されている。

この文脈において、オーケストレーションとは、システムやチームをまたいで作業を調整することを意味する。ネットワークアラートはインシデントの一部を示す一方で、サービスチケット、アプリケーションの問題、インフラストラクチャの変更が追加の文脈を提供することがある。DXC が掲げる目的は、これらの要素をひとつにまとめ、チームが調査から承認された対応へと進めるようにすることである。

この協業は、Cisco のネットワーク機能を、そのより広い運用上の文脈と接続することを意図している。Cisco はネットワークインテリジェンスとプラットフォームネイティブなアクションを提供し、OASIS は企業のワークフローをまたぐ作業の調整を支援する。

DXC の Global Infrastructure Services 社長である Dan Gray は、提供された発表の中で目的を次のように述べた。

「企業のチームに必要なのは、より多くのアラートではありません。解決へのより速い道筋です。」

これは同社が掲げる目標であり、リリースは、この特定のインテグレーションについて独立して検証された結果を提供していない。

なぜ Meraki の Wi-Fi インシデントから始めるのか？

当初の焦点は、Cisco Meraki 環境におけるワークプレイスの Wi-Fi パフォーマンスである。Wi-Fi の問題は、従業員がアプリケーションにアクセスしたり、会議に参加したり、日常業務を完了したりする能力に影響を及ぼしうるため、ネットワークのトラブルシューティングにおける実用的な出発点となる。

発表によると、この取り組みは、チームがパフォーマンス上の問題を特定し、考えられる根本原因を調査し、対応を調整するのを支援することを意図している。このアプローチの一部として、Cisco の AI Assistant、Experience Metrics、およびプラットフォームネイティブな機能が挙げられている。

リリースは、サポートされるインシデントの種類やアクションの詳細な一覧を提供していない。また、すべての Meraki 顧客がすでにこのインテグレーションを利用できるとも述べていない。

関連する記事については、TechnoSports でエンタープライズネットワーキングとAIエージェントを検索のこと。

提案されたワークフローはどのように役立ちうるか？

例示的なインシデントは、従業員が無線パフォーマンスの低下を報告することから始まる場合がある。ネットワークツールが関連情報の表面化を助ける一方で、運用チームは、その問題がアプリケーションやサービスチケットにも影響しているかどうかを確認する。

発表で説明されているアプローチの下では、DXC OASIS は、それらのシステムをまたぐ調査と承認済みアクションの調整を支援する。人間のオペレーターは、監督、ガードレール、変更の追跡を通じて関与し続ける。

リリースは、正確なステップごとのワークフローを示しておらず、人が毎回すべてのアクションを手動で承認しなければならないとも述べていない。このインテグレーションを評価する組織は、どのアクションを自動化でき、どのアクションにレビューが必要かを確認する必要がある。

MCP の役割とは何か？

DXC によると、このインテグレーションは、Cisco の AI Assistant と Model Context Protocol (MCP) ツール を OASIS に接続する。MCP は、AIアプリケーションがツールやデータソースに接続するのを支援するために設計されたプロトコルである。その公式ドキュメントは、このプロトコルの仕組みに関する背景を提供している。

発表では、このインテグレーションの技術アーキテクチャ、権限、導入要件は説明されていない。また、MCP を使うだけでは、アクセスが安全であること、あるいはAIが生成した推奨が正しいことは保証されない。それらは実装、制御、レビューに依存する。

DXC はパイロットについて何と述べたか？

DXC は、同社のより広範なエージェント型AIの取り組みにおける1件のパイロット で、インシデント解決時間が 1〜2時間 から 5〜7分 に短縮されたと報告している。

これは同社が報告した注目すべき結果だが、文脈の中で捉えるべきである。発表は、そのパイロットが新たに発表された Cisco のインテグレーションを使用したものであるとも、Meraki の Wi-Fi インシデントを対象としたものであるとも述べていない。また、サンプルサイズ、インシデントの種類、測定方法も開示していない。

したがって、これらの数値は、1件のパイロットで可能だったと DXC が述べていることを示すものであり、この協業を採用する顧客にとって保証された結果ではない。

Cisco の Network Platform and Assurance 担当シニアバイスプレジデント兼ゼネラルマネージャーである Joe Vaccaro は、このインテグレーションは、人間のチームを主導権を握ったままにしつつ、統制されたネットワーク自動化を、サービス管理ツールを含む企業の文脈と接続することを意図していると述べた。

導入前に企業は何を確認すべきか？

発表は方向性を示しているが、自社の運用に適合するかどうかを評価するには、企業はより詳細な情報を必要とする。有用な質問には次のものがある。

  • 提供開始時期とコスト: このインテグレーションはいつ利用可能になり、どのようなライセンスやサービスが必要になるか？
  • データアクセス: どのネットワーク記録とインシデントの詳細が OASIS やAIシステムと共有されるか？
  • 権限: エージェントはどのアクションを提案または実行でき、誰がそれを承認するか？
  • 変更の追跡: 決定、アクション、結果はどのように記録され、レビューされるか？
  • 既存のツール: どのサービス管理システムやインフラストラクチャシステムを接続できるか？

組織は、AIの推奨を自社のインシデント手順に照らしてテストしたいと考えることもある。より速い対応が価値を持つのは、チームが変更を理解し、レビューし、必要な場合には元に戻せる場合に限られる。

次に何が来るか？

DXC は、最初の Meraki の取り組みを、追加の Cisco テクノロジーへ拡大するための 再現可能なモデル として使いたいと述べている。提供された発表は、それらのテクノロジーの名前も、スケジュールも示していない。

同社はまた、OASIS を、オープンでパートナー主導のオーケストレーション戦略の一部と説明している。導入、サポートされるインテグレーション、顧客の成果に関するさらなる詳細は、この協業が実際にどのように機能するかを評価する上で重要となる。

このインテグレーションはインドで利用できるか？

発表にはインドのデートラインがあるが、地域ごとの展開日は示されておらず、一般提供も確認されていない。

DXC は、このモデルを追加の Cisco テクノロジーに拡大することを目指していると述べているが、一覧もスケジュールも示していない。
