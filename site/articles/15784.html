Ubuntu Core Desktop、28.04でのデビューを目標に、デフォルト化も視野

Ubuntu Core Desktop targets 28.04 debut, with default status in its sights
The Register (Networks)2026-11-20 21:00報道

Canonical は、イミュータブルな Core Desktop のリリースを Ubuntu 28.04 LTS で目指しており、Ubuntu 30.04 でこれをデフォルトのダウンロードにするというストレッチ目標も掲げている。

Canonical のエンジニアリング担当 VP である Jon Seager は、Ubuntu Summit 26.10 の冒頭基調講演でこのスケジュールを示した。そう、これは以前にも聞いた話だと我々も承知している。先月、彼の計画を報じた。しかし今回は、リリーススケジュールの始まりがある。

Seager は、Ubuntu Core はすでに何万台もの IoT デバイスに搭載されていると述べた。これは我々にとっても彼にとっても控えめな見積もりに思え、彼自身もすぐに「もっと多いかもしれない」と付け加えた。ただ、数年前にいくらか騒がれたにもかかわらず、まだ欠けているのはデスクトップ版である。

Seager のスライドには 3 つの箇条書きが並んでいた。Core Desktop は「イミュータブル」「コンポーザブル」「アテスタブル」になる、というものだ。

彼の言葉では、彼らは「Linux オペレーティングシステム全体を取り込み、その全体を snap の中に詰め込んでいる」。これが大きな論争を呼ぶことを認めた上で、彼は「これは Redditor 向けだ」と述べた。

その通りである。snap への抵抗は大きく、それに直接対抗して、代わりに Red Hat が支援する Flatpak を支持する声もある。しかし、どちらのシステムの技術的な優劣に基づいたものも、我々はほとんど見たことがない。その反対論の多くは、一方が他方よりオープンであるという主張に関するものだ。我々は両システムの仕組みを調べたが、snap の実装のほうがよりクリーンで、よりシンプルで、より使いやすく、より理解しやすいという印象を持っている。snap は systemd に依存しているが、Flatpak は依存していない。ただし、それは今のところに限る。Flatpak NG が開発中であり、こちらも皆のお気に入りの init システムを必要とすることになる。

Ubuntu Core のイミュータビリティは新しい技術ではない。Core 16 でさえ、すでに 10 年前のものだ。Core 22 以降、インプレースのバージョンアップグレードをサポートしている。

我々は以前、Canonical が自社のパッケージ形式に強くコミットし続けていると報じたが、そのコミットメントはこれまで以上に強いようだ。Seager は続けた。「snap のコンファインメントのようなモデルが、これほど重要になったことはない…… ついにこれをデスクトップにもたらせる立場に立った。」

イミュータブルな OS の中核となる考え方は、「システムのはるかに多くの部分が実行時に書き込み不可になる」ということであり、つまり「システムが一度起動したら、いじることができない」ということだ。彼は、我々が先月取り上げたものと同じ 3 つのユースケースについて語った。「ブラウザ中心のマシン」は、同社版の Google ChromeOS に相当するもので、基本的に今すぐ使える状態にあると彼は述べ、聞いている人のほとんどには、コンピューターが基本的に Web ブラウザを使うための手段でしかない家族がおそらくいるだろうと示唆した。

2 つ目は専用のゲーミングマシンで、我々はこれを Valve の SteamOS への対応と解釈している。このエディションは「Steam に直接ブート」し、「ゲームを起動するのにちょうど足りるだけのシェル」を備えるという。イミュータブルな「開発ワークステーション」もあり、ここで彼は、長年サポートされていないハードウェアやソフトウェアで作業する必要がある開発者の例を挙げた。そうした開発者にとって、イミュータブルな OS であれば「20 年間メンテナンスされていない奇妙な古い依存関係をインストールしても、システムを文鎮化させることはない」。

もう一つの重要な利点は「アトミックでトランザクショナルなアップデート」であり、彼はこれが「非常に大きな安定性をもたらす」と述べた。この用語はデータベースの世界に由来する。アトミックな操作は、全体として成功するか、まったく適用されないかのどちらかである。その狙いは、互換性のないパッケージバージョンの間でシステムが立ち往生するのを避けることであり、アップデートで問題が起きた場合にはロールバックによって元に戻る道が用意される。

Ubuntu エンジニアリング担当 VP Jon Seager

「コンポーザブル」の部分は、デスクトップ環境から、PipeWire や指紋リーダーのサポートといった基盤サービスに至るまで、個別にパッケージ化されたコンポーネントから OS を組み立てることを意味する。

ここで Seager は、我々の心に響く例を使った。彼は「何かをインストールして、それがシステム中にあれこれ撒き散らすのを見たことはないか」と尋ねた。ある、何度も何度もある。無害に見える小さなコンポーネントを 1 つインストールすると、データベース、3 つの新しいサーバーコンポーネント、そして別のデスクトップ環境の約半分が入ってくる。数か月前に Xfce のカスタマイズ方法を解説した際に、その例に触れた。そのとき Debian では、「xfce4-」で始まるすべてのパッケージは、「xfce4-dev-tools」を除いて安全にインストールできることがわかった。ほとんどは数百キロバイトしかない小さなパネルコントロールだが、「dev-tools」パッケージは、デスクトップのレイアウトとは全く無関係な、数百メガバイトものコンパイラ、リンカ、その他のプログラミングツールも引き込む。そして一度インストールすると、再び削除するのは意外に厄介である。

これが、コンポーザブルなイミュータブル OS の魅力の一部である。コンポーネントを追加しても、その依存関係をベースシステムに絡ませる必要がない。しかし、後片付けが楽になることだけが魅力ではない。Canonical は、中止されたスマートフォンとタブレット向け OS の snap パッケージを残した。snap によって、たとえば Firefox のパッケージを 1 つ維持するだけで、まだアップデートを受けているすべての異なる OS バージョンで動作させられるからだ。このような重要な外部依存関係を隔離された snap パッケージに移すことで、ある OS バージョンから別のバージョンへのアップグレードがより容易かつ安全になる。複雑な依存関係の集合は、特に OS をしばらく使用した後では、OS アップグレードにおける主な失敗要因である。

これは決して解決済みの問題ではない。たとえば、Debian のバージョンアップグレードは、特にインストールに数十年の履歴がある場合、困難を伴うことがある。Debian は少なくともバージョン間アップグレードをサポートしている。RHEL は長年、何バージョンにもわたってそうではなかった。だからこそ我々は、そのための AlmaLinux のツールを取り上げた。Zorin OS は、ほんの数年前の 16.3 でバージョン間アップグレードを追加した。Linux Mint は、その数年前に独自のアップグレードツールを導入したが、今でも制限がある。

これは解決の難しい問題である。大手エンタープライズベンダーはこれを推奨せず、スマートフォンの OS はすべてイミュータブルである。この問題の解決に役立つことは、snap パッケージングが存在する主な理由の一つであり、一方 Flatpak はこれにはほとんど無関係である。

Seager はまた、Core Desktop が「最初から複数のデスクトップ」をサポートすると述べた。これは GNOME だけのプロジェクトにはならない。実際、彼は KDE Plasma 版に特に言及し、こう述べた。「Plasma は素晴らしい。人々に愛されている。我々は、ローリングの Plasma を備えた KDE エディションを用意する。アップストリームの Plasma を、できる限り早く提供する。」これは、8 月に発表を取り上げた Kubuntu 26.04 の LTS 版 Plasma 6.6 に対する、非常に歓迎すべき対比に聞こえる。

スライドの「アテスタブル」の行について、彼は Core Desktop が「マシン上の『信頼』についての考え方を進化させている」と主張した。「TPM、セキュアブート、TPM に支えられたフルディスク暗号化はあるが…… それらはどれも後付けだ。」Core Desktop は、これを「ハードウェアルートオブトラスト」に結び付け、「検証されたシステム完全性」を提供できると彼は付け加えた。Canonical は 2025 年に TPM に支えられたフルディスク暗号化システムを復活させ、それは Ubuntu 26.04 で登場した。1 月には、systemd の作者である Lennart Poettering がスタートアップ Amutable を立ち上げ、今月初めにはその新しいイミュータブル Linux の技術概要を公開した。我々は、Canonical が注視しており、これがその方向へのヒントなのではないかと推測している。

我々はまた、Seager が別のかなりニッチなディストロに言及したことにも面白さを感じた。彼は、Core Desktop は「NixOS から人々が得ているあらゆる喜びを、その倒錯した習慣を持つ人々のためだけでなく、すべての人に」提供すると述べた。

Core Desktop のデイリープレビューインストールイメージは、GNOME と KDE の両フレーバーで、まもなく利用可能になるとのことで、彼は「ここにはドラゴンがいる」と警告した。（これは、創設者 Mark Shuttleworth の別の会社への遠回しな目配せかもしれない。）

2023 年に行われた約束の後だけに、我々はそのスケジュールを注意深く見守るつもりだ。「これが Linux の未来だと信じている」と Seager は述べ、「28.04 までに、Ubuntu と同時にリリースされる最終版」を約束し、さらに「非常に伸びのあるストレッチ目標は、30.04 でのデフォルト化：ubuntu.com からダウンロードすると Core Desktop が手に入る。ただし、もう一方のものを求めた場合は別だ」と付け加えた。
