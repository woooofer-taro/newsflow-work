Cloudflareが新たな5件の脆弱性のうち3件からnginxオリジンを保護

Cloudflare Shields nginx Origins From Three of Five New Flaws
Technobezz2026-11-27 07:00報道

Cloudflare は、同社の HTTP プロキシは、攻撃者がそれを迂回してサーバーに直接到達できない限り、新たに公開された HTTP/2 および HTTP/3 に影響する 3 件の脆弱性から nginx サーバーを保護すると述べている。管理者は nginx 1.30.7、nginx 1.31.9、または修正済みのベンダービルドをインストールし、その後再起動するよう同社は勧告している。この保護は、別のリゾルバーの脆弱性を完全にはカバーせず、メールプロキシの脆弱性もカバーしない。

F5 と nginx.org は 11 月 18 日に 10 件の nginx 脆弱性を公開した。その中には、Xint が nginx2root の名称で調査した 5 件のメモリ破壊バグが含まれる。これら 5 件は、認証なしの攻撃者がワーカープロセスをクラッシュさせたり、Xint によればサーバーコマンドを実行したりすることを可能にし得る。F5 はそれぞれに CVSS 4.0 スコア 9.2（Critical）を割り当てており、コードの実行には Address Space Layout Randomization の突破または無効化が必要だと述べている。

Cloudflare は、HTTP/2 を有効にするだけで影響を受ける機能が露出するため、CVE-2026-123007 を最大の懸念として挙げている。この機能は nginx 1.9.5 に遡る。Censys は、11 月 19 日時点で HTTP/2 を有効にした、脆弱な可能性のあるバージョンを使用しているサービスを約 880 万件と数えた。Cloudflare は、ディストリビューションが古いビルドに修正を取り込んでいる可能性があるため、報告されるバージョン番号だけでは脆弱性を判定できないと注意を促している。

プロキシ対象のホスト名については、Cloudflare がクライアントの HTTP/2 または HTTP/3 接続を自身で処理し、その後オリジンとの間に別の接続を確立する。同社は、オリジンへの自社の接続が HTTP/2 を使用している場合でも、これにより悪意あるプロトコルフレームが nginx に到達しないと述べている。しかし、オリジンの IP アドレスに直接接続できる攻撃者はこの保護を迂回でき、オリジンへのアクセス制限がこの保護の条件となる。

リゾルバーの脆弱性は、proxy_pass、変数、サブリクエストを含む設定選択の組み合わせに依存する。Cloudflare は、同社のプロキシはこれに対する完全な保護を提供できないと述べている。メールの欠陥には、proxy on と auth_http を使用する nginx メールプロキシが必要であり、Cloudflare の HTTP プロキシはメールを転送しない。Cloudflare は、自社のエッジは影響を受けず、関連する経路に対処する更新が公開前に世界中に展開されたと述べている。

Xint はまた、nginx ワーカーとしての実行を root アクセスに変え得る Linux カーネルの欠陥を発見し、Docker コンテナ内からその権限昇格を実証した。11 月 18 日時点でカーネルの修正は利用できず、Xint はパッチが出るまで詳細を伏せていた。Cloudflare は、Rapid7 が限定的な概念実証を公開していたものの、11 月 19 日時点で 5 件の nginx 脆弱性を悪用する攻撃が実際に確認されたという報告は見ていないと述べた。
