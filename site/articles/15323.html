AIの「ブラック・オクトーバー」はコードを守る方法を変えましたか？

Has AI’s ‘Black October’ changed the way you secure your code?
The Register (Networks)2026-11-17 07:00報道

AIの「ブラック・オクトーバー」はあなたのコードの守り方を変えたか？

パートナーコンテンツ：AIエージェントによって、コード内のセキュリティ脆弱性の発見と悪用が容易になっている。ソフトウェアエンジニアリングおよびアプリケーションセキュリティのチームには、それらを見つけて修正する新しい方法が必要だ

2026年10月は、ソフトウェア開発者とアプリケーションセキュリティチームにとって画期的な瞬間として記憶されるかもしれない。AIエージェントは未知のシステムを調査し、侵入方法を試し、試行が失敗すれば次の手を調整している。クレジットカードを持つ人なら誰でも、その能力を使ってあなたのアプリケーションを狙うことができる。

コーディングエージェントとそのツール連携は、悪用され得る新たな侵入口と攻撃対象領域をもたらした。10月のPillarによるOpenCodeの開示は、悪意あるModel Context Protocol（MCP）サーバーが、認証中に開発者のWindowsまたはWSLマシン上でコマンドを実行し得ることを示した。サーバーから提供されたURLが、モデルを騙すことなくシェルに到達した。同じ月に、OpenAIのモデルの助けを借りて発見されたPHPランタイムのリモートコード実行バグである2件のPHP2Shell脆弱性が発見され、インターネットの大部分にわたる長年のコードを保護することに新たな緊急性をもたらした。

Microsoftは、あるエージェントが、GitHubで露出した認証情報を検索する段階から、5分でAzure Key Vaultのデータを盗む段階へ移行したと明らかにした。クラウドAPIリクエストが失敗すると、エージェントはAPIバージョンを修正し、成功するまで再試行した。

Anthropicの報告書は、これまで専門家チームを必要としていた複数の被害者を狙うキャンペーンのために、個々の運用者がエージェントフレームワークを使用していると述べた。エージェントは複数の標的にわたって並行して偵察、悪用、データ窃取を実行し、手作業を減らして高度な作戦を利用しやすくした。

これらの新たなエージェント型攻撃により、すべてのチームは長年運用してきたコードをもう一度見直すべきである。エンジニアリングチームとセキュリティチームは、AIエージェントの軍勢を持つ攻撃者が先に到達する前に、自社のアプリケーションの弱点を見つけて修正する必要がある。

セキュリティはすべての開発者の責任にならなければならない

ルールベースの静的解析、依存関係スキャン、シークレット検出といった従来のAppSecチェックだけでは、もはや十分ではない。開発者、エンジニアリングリーダー、セキュリティチームには、攻撃経路を追跡し、欠落している保護策やビジネスロジックの脆弱性を発見し、それらの修正を支援する防御側のAIエージェントも必要である。

開発者の責任は、現在書いているコードで終わらない。既知の脆弱性がない状態で本番稼働しているアプリケーションでも、権限チェックやビジネスルールを回避する方法を探すAIエージェントによって悪用される可能性がある。そのギャップは、リクエストをコードベース全体で追跡し、ユーザーに許可されるべきことと照らし合わせて確認したときに初めて現れる。

コードを保護する新しいアプローチ

CodeRabbit Secureは、セマンティック分析を用いてコードベースを理解し、セキュリティエンジニアのようにそれについて推論する。リクエストを追跡し、権限やビジネスルールが適用されているかを確認する。エージェントは、潜在的な攻撃経路を調査し、コードを書いた開発者やエージェントとは独立に発見事項を検証し、CodeRabbit Agentはレビュー可能な修正を生成する。

コードセキュリティを向上させる3つの主な使用例：これはSDLC全体で機能する：

新しいPR内の各コミットをレビューし、そのセキュリティリスクにフラグを立てる。

Deep Scanでリポジトリ全体の脆弱性を見つける。

増分スキャンでコードを再チェックし、実行時に発見事項を検証する。

コミット済みコードにすでにある脆弱性を見つける

Deep Scanは、最新のPRの外にある古い経路を含め、リポジトリを調べる。エージェントはエントリポイント、アクセス制御、機密性の高い操作をマッピングし、その後、関数やファイルをまたいで調査する。設定されている場合、リンクされたリポジトリが、共有サービスやライブラリからのコンテキストを提供する。別のエージェントが、疑わしい各脆弱性に異議を唱え、到達可能性、悪用条件、およびそれを反証し得る保護策を確認する。

ast-grepに対してCodeRabbit Secure Deep Scanを試し、その精度に感銘を受けた。フラグを立てる前に脆弱性を証明することで、すべての発見事項がはるかに実行しやすくなる。
Herrington Darkholme、ast-grep作者

マージ前に受け入れる変更をレビューする

PRセキュリティレビューは、エージェントが生成したコードを含む各受け入れ変更を、既存のアプリケーションで到達可能かつ悪用可能な脆弱性について評価する。

CodeRabbitのSecurity Architecture Reviewは、アーキテクチャレベルの変更が権限、機密データフロー、信頼境界にどのように影響するかを調べる。Security Blast Radiusマップは、変更されたコンポーネントを、その依存関係およびそれらに依存するコードに結び付け、レビュアーがPR diffを超えた潜在的なセキュリティ影響を追跡するのを支援する。

GitHubでは、管理者はCodeRabbit Security checkを有効にし、ブランチ保護またはルールセットを通じて必須にできる。設定された重大度しきい値以上のPRセキュリティコメントが未解決のまま残っている場合、マージをブロックする。

コードの進化に合わせて再チェックし、実行時に発見事項を検証する

各Deep Scanはリポジトリの攻撃対象領域マップを構築し、セキュリティ関連のどのエントリポイントが検証済みか、コードの変更により古くなったか、一度も調査されていないかを示す。その後、Deltaスキャンが、変更されたファイルと、マップ上の古くなった、または未検証の領域をチェックするため、チームはコードベースのどれだけがセキュリティレビューされ、最後にいつレビューされたかを把握できる。個々の発見事項も再チェックして、修正がそれに対処したかどうかを判断できる。

GitHub Cloud上でCodeRabbit Cloudを使用する対象のDeep Scan発見事項については、実行時検証が再現ガイドを生成し、隔離された環境でそれを実行して、脆弱な経路に到達するかどうかを確認できる。結果は、テストしたリビジョンと環境について「reproduced」「not reproduced」「inconclusive」のいずれかとなるが、再現に失敗しても、発見事項が修正されたことを意味しない場合がある。

調査を修正まで持ち越す

開発者はCodeRabbit Agentに修正の実装とPRのオープンを依頼し、その後、発見事項、提案された修正、裏付けとなる証拠を検査できる。チームは重大度しきい値を設定して、JiraまたはLinearのチケットを自動的に作成し、既存のワークフローで修復を追跡することもできる。

脆弱性の発見事項、その裏付けとなる証拠、提案された修正を結び付けることで、コンテキストがまだ新しいうちに、エンジニアリングチームとセキュリティチームが行動し、変更をレビュー、テスト、リリースまで進めるのに役立つ。チームはCodeRabbit Agentを使ってそのコンテキストに基づいて行動することも、共有可能なmarkdownファイルで好みのコーディングエージェントに簡単に引き継ぐこともできる。

100万ドル規模の取り組みが明らかにしたこと

CodeRabbitは最近、組織が隠れた脆弱性を見つけて修正するのを支援するため、最大100万ドル分の無料Deep Scanを提供することを約束した。11月上旬の10日間に作成されたDeep Scanで、CodeRabbit Secureは約2,000組織にわたり、約53,000件のHighまたはCriticalの発見事項を記録した。10,000件を超える発見事項がすでに修正されており、その中にはHighまたはCriticalと評価された1,049件が含まれる。

CodeRabbitが実施したセキュリティ修正の一部には、次のものを防ぐものがあった：

リポジトリドキュメントのメタデータに埋め込まれたJavaScriptが任意のコードを実行すること。

メールの件名が実行可能なテンプレートとして解釈され、APIサーバーの権限でJavaScriptが実行されること。

認証されていない送金リクエストがSQLを注入し、不正なデータベース操作を引き起こすこと。

エージェントがより多くのコードを生成し、攻撃者がより高い能力を持つようになるにつれ、セマンティック分析を用いた調査は、既存のセキュリティチェックと並んで、ソフトウェアの構築と保守の定常的な一部になる必要がある。

攻撃者より先に、あなたのコードの脆弱性を見つける

攻撃者がAIエージェントを使って未知のシステムを調査し、次の手を調整する中、エンジニアリングチームとセキュリティチームには、自社のコードを調査し、発見事項をテスト済みの修正まで持ち越すための同等の能力が必要だ。
