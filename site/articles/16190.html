Broadcom、新たな23件のVMware脆弱性の修正を公開、うち3件は重大

Broadcom issues fixes for 23 new VMware flaws, three critical
Network World2026-11-26 07:00報道

最も深刻なもの：vCenterの認証バイパスのバグであり、米国のサポートチームの感謝祭の休日を台無しにするのにちょうど間に合うタイミングである。

Broadcomは火曜日、VMwareにおける新たなセキュリティ脆弱性をほぼ24件報告した。これは、今月だけでも多数にのぼる修正の一覧に加わるものである。

今回のアドバイザリーにある脆弱性のうち最も深刻なものは、vCenterの認証バイパスの脆弱性であるCVE-2026-123903で、CVSSv3基本スコアは9.8（Critical）と評価されている。「vCenterにネットワークアクセスできる悪意ある攻撃者は、この問題を悪用して認証を回避し、システムへの不正アクセスを得る可能性がある」と同アドバイザリーは述べている。

Broadcomは、アラートに付属する補足文書の中で、協調的開示とリリースパイプラインのタイミングの都合により、このアドバイザリーが米国の感謝祭の休日のわずか2日前になったと記し、「このタイミングは最適ではない」と認めた。

同社によれば、このアドバイザリーは合計23件の問題を対象としており、そのうち7件はvCenterにある。内訳は、VMware Directory Serviceにおける認証バイパス1件とサービス拒否の問題3件、特定のアーカイブの処理中における任意ファイル書き込み、vpxdサービススクリプトにおけるローカル権限昇格、そしてvSphere Distributed Switch（vDS）におけるセキュリティポリシー適用の失敗である。

さらに7件はESXにあり、I/Oフィルターサービスにおけるヒープの境界外書き込みと use-after-free、Extensible Host Controller Interface（XHCI）USBコントローラーにおける境界外書き込み、VMkernelにおけるスタックベースのバッファオーバーフロー、ホスト構成ストアにおけるセキュリティバイパス、署名検証のバイパス、そしてゲストRPCにおけるサービス拒否である。

残りの脆弱性は、VMware Workstation、VMware Fusion、VMware Tools、VMware Avi Load Balancerに影響する。

ただし同社は、先週のアドバイザリーの脆弱性に対処するために提供された修正が、今回の一群で強調されている問題のいくつかを解決していると述べた。

「VMSA-2026-0009 向けに vCenter 8.0 U3m を適用済みの場合（VCF 5.2.x 上を含む）、vCenterを再度更新する必要はないが、vCenter 9.1.x には本アドバイザリーの更新が必要である」とBroadcomは述べた。

「ESXはVMSA-2026-0009の対象ではなく、本アドバイザリーの更新が必要である。VMSA-2026-0009ではSDDC Managerの問題も解決されたが、本アドバイザリーはこれを更新しない。VMSA-2026-0009のSDDC Manager更新を適用していない場合は、別途適用すること。本アドバイザリーにはVMware Toolsの更新も含まれる。vCenterとESXを更新しても、仮想マシン内のVMware Toolsは更新されないため、その更新は別途計画すること。」

同社はさらに、「自社が影響を受けるかどうかについて疑問がある場合、影響を受けている可能性が高く、直ちに対応すべきである」と付け加えた。

パッチ適用の緊急性をめぐる意見の相違

では、これらの脆弱性に対処するために米国の感謝祭の休日を中断すべきというシグナルなのだろうか。意見は分かれている。

Fortraのセキュリティ研究開発担当アソシエイトディレクターであるTyler Regulyは、9.8というスコアは最高に近いものの、これらの欠陥の性質は極端なスケジュール対応に値しないかもしれないと主張した。今回の一群には深刻度9.8と評価された脆弱性が3件あり、VMware vCenterとESXに影響する。

彼は次のように指摘した。「これら［影響を受ける］システムはどちらも外部インターフェース上に存在すべきではなく、したがってリスクは内部からのものである必要がある。つまり、内部脅威、あるいはすでに進行中の侵害の話をしているということだ。これらは重要な脆弱性であり、その点に疑いはないが、誰かが週末の休日を中断すべきほど重要ではない。」

Regulyは、これらのパッチが緊急対応に値しない可能性があるという自身の主張を裏付けるため、CISAのガイダンスの厳格な解釈を示した。

「この件のガイダンスとしてCISA BOD-26-04を見るなら、そのサービスは公開されているか。公開されているべきではないので、いいえとしよう。この脆弱性はKEV［Known Exploited Vulnerabilities catalog］に含まれているか。いいえ。自動化できるか。不明なので、念のため可能と仮定しよう」と彼は述べた。「いいえ、いいえ、はいという結果は、BOD-26-04の修復期限の13行目に相当し、問題の修正に60日が認められている。」

彼は、最近の脆弱性の猛攻により、私たちは「少しパブロフの犬のよう」になっていると述べた。CVSS 9.8を目にするたびに反応するよう条件づけられてしまっているのである。

「これは危険で、潜在的に有害な条件づけであり、断ち切るためにあらゆる努力をする必要がある」と彼は述べた。「ベルが食べ物を表していなかったのと同様に、脆弱性の深刻度は組織にとってのリスクを反映しないということを、私たちは自分自身に思い出させる必要がある。」

Dickson ResearchのプリンシパルアナリストであるFrank Dicksonは、これに異を唱えた。

彼は今回のアドバイザリーVMSA-2026-0011について、「すべての仮想マシンを動かす2つのシステムであるvCenterとESXに、パスワードを必要としない欠陥で影響するため、大きな問題だ。パッチを適用しなければ、1人の攻撃者が、あなたが運用するすべての仮想マシンを停止させる、あるいは乗っ取ることができる。あなたは基本的にもう終わりだ。今すぐパッチを適用せよ」と見なした。

Dicksonは、この一群のアラートには複数の問題のあるセキュリティ上の問題が含まれていると指摘した。それらには、vCenterにおける認証バイパス、ネットワークアクセスを持つ攻撃者がハイパーバイザー自体でコードを実行できること、そしてWorkstationまたはFusion上の仮想マシン内の管理者がホストコンピューター上でコードを実行できるもう1つのバグが含まれる。「正直に言おう。AIは脆弱性を連鎖させるのを好む」と彼は述べた。

彼はまた、今月だけでVMwareのパッチが多数あること、特にvCenterのものについて懸念している。「VMwareのvCenterの欠陥の頻度は懸念事項だ。同じ場所に何度も現れ続けているからだ」と彼は述べた。「新しい欠陥は先週のものとは別物である。別物であることは安心材料にならない。同じ壁に3つの異なる穴があるのは、壁の問題だ。」

彼は次のように指摘した。「ディレクトリサービスはvCenterのアキレス腱になっている。このアドバイザリーは、念のため、同じサービスにさらに3つのサービス拒否の欠陥を加えている。」
