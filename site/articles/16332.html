Synology DSM OAuthの脆弱性（CVE-2026-120382）とNGINX2Rootの修正：今すぐDSMにパッチを適用

Synology DSM OAuth Flaw (CVE-2026-120382) and NGINX2Root Fixes: Patch DSM Now
Rescana2026-11-27 21:00報道

状況: 2026年11月19日、Synologyは同社NASデバイス向けオペレーティングシステムについて2件のセキュリティアドバイザリを公開した。Synology-SA-26:21 は CVE-2026-120382 を扱っており、これはDiskStation Manager（DSM）およびBeeStation OSのOAuth APIにおける、これまで公表されていなかった脆弱性で、Synologyは「リモートの攻撃者が任意のファイルを読み取りまたは書き込みし、サービス拒否攻撃を行うことを可能にする」としている。SynologyはこれにCVSS 3.1で9.8を付けている。Synology-SA-26:20 は、F5とnginxプロジェクトが「NGINX2Root」の一連の脆弱性の一部として11月18日に公表した、NGINX HTTP/2の脆弱性 CVE-2026-123007 に対する、DSM、BeeStation OS、DSM Enterprise、およびSynologyのAPMオペレーティングシステムでのSynologyの修正である。11月20日、Synologyは両アドバイザリを改訂し、最初の修正済みリリースである DSM 7.4.1-90080-2 と DSM 7.3.2-86009-6 を掲載した。DSM 7.2.2、7.2.1、7.1、およびBeeStation OS 1.5向けの修正は、まだ「OnGoing」と表示されている。デバイスが更新されるまで、Synologyの暫定的な緩和策は、OAuth Serviceパッケージを無効化することと、HTTP/2を無効化することである。Synologyは「これらの脆弱性の悪用は確認されていない」としている。CVE-2026-120382 はCISAのKnown Exploited Vulnerabilities（KEV）カタログに含まれていない。CVE-2026-123007 はCISAのKnown Exploited Vulnerabilities（KEV）カタログに含まれていない。我々は2026年11月21日の15:41 ESTと再度15:44 ESTにcatalogVersion 2026.11.20を確認した。このカタログは2026年11月20日12:48 ESTに公開されたもので、1,790件のエントリを含む。全ソースの最終確認は 2026年11月21日の15:41から15:49 EST の間に行った。

エグゼクティブサマリー

OAuth Serviceは、サードパーティアプリケーションがユーザーパスワードの代わりにトークンを通じてDSMサービスへのアクセスを取得できるようにする、Synologyのパッケージである。Synologyのリリースノートは、初版以来これを「組み込みパッケージ」と説明している。SynologyのアドバイザリはCVE-2026-120382をOAuth APIに位置付けており、リモートの攻撃者がこれを使ってデバイス上の任意のファイルを読み取りまたは書き込みし、サービス拒否を引き起こせるとしている。Synologyは、脆弱なエンドポイント、関与するコマンド、またはリクエストパターンを公開していない。

計画にあたって重要な点:

  • ログインは不要である。 SynologyのCVE-2026-120382のCVSSベクトルは、ネットワーク攻撃元区分、権限不要、ユーザー操作不要となっている。
  • 修正はパッケージの更新ではなくDSMの更新である。 Synologyが挙げる修正済みリリースはDSMのビルドである。Synologyのリリースノートにおける最新のOAuth Serviceリリースは、依然として2026年6月16日の1.3.0-0220である（Rescanaによるリリースノートの解釈）。
  • これまでに修正があるのはDSM 7.4とDSM 7.3のみである。 Synologyは、DSM 7.2.2および7.2.1のユーザーに7.3.2-86009-6への移行を推奨している。DSM 7.1とBeeStation OS 1.5にはまだ修正済みリリースがないため、現時点ではそれらのデバイスを守るのは緩和策のみである。
  • 同じ2つのDSMビルドはCVE-2026-123007も修正する。 その脆弱性には公開されている概念実証コードがあり、作成者はそれが限られた条件下でのみ動作すると説明している。これについては、当社のNGINX HTTP/2アドバイザリで詳しく扱っている。
  • 悪用の報告はない。 Synologyは確認されていないとしており、我々はCVE-2026-120382の公開されたエクスプロイトコードを見つけられなかった。

最初に対応すべき対象（Rescanaのガイダンス）。 DSMまたはBeeStationのウェブインターフェースに、ポートフォワーディング、リバースプロキシ、またはその他のリモートアクセス経路を通じてインターネットから到達できるSynologyデバイスの所有者、まだ修正がないDSM 7.1またはBeeStation OS 1.5のデバイス、そして貴社のファイルやバックアップをSynology NAS上に保管しているサプライヤー。

技術情報

CVE-2026-120382、Synologyによる説明。 「Synology DiskStation Manager（DSM）の6.2.4-25556-9、7.1.1-42962-10、7.2.1-69057-14、7.2.2-72806-11、7.3.2-86009-6、および7.4.1-90080-2より前のバージョンのOAuth APIにおける、コマンド内の引数区切り文字の不適切な無害化の脆弱性により、リモートの攻撃者が任意のファイルを読み取りまたは書き込みし、サービス拒否攻撃を行うことが可能になる。」SynologyはCVSS 3.1ベクトル `CVSS:3.1/AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:H/A:H`、基本スコア9.8、および弱点CWE-88、コマンド内の引数区切り文字の不適切な無害化を示している。アドバイザリは報告者を挙げていない。

ここでCWE-88が意味すること（Rescanaによる要約）。 引数インジェクションの脆弱性では、プログラムに渡される1つの値になるはずの入力が、追加のオプションや引数に分割される。その結果、プログラムは呼び出し元が意図しなかったこと、たとえば触れるはずのなかったファイルの読み取りや書き込みを行う。これはSynologyが挙げている影響と一致する。Synologyはこの脆弱性がコマンド実行を可能にするとは述べておらず、我々もそう主張しない。ストレージデバイス上での任意のファイル書き込みは、それ自体で深刻である。デバイスはデータを保持しており、その上の一部のファイルはシステムの挙動を制御する（Rescanaの解釈）。

説明に記載されているがまだ公開されていないビルド。 CVEの説明は、現在入手可能な2つのリリースに加えて、DSM 6.2.4、7.1.1、7.2.1、および7.2.2の修正済みビルドを挙げている。11月20日12:19 EST、ならびに11月21日15:42 ESTと15:48 ESTの時点で、Synologyのダウンロードアーカイブには6.2.4-25556-9、7.1.1-42962-10、7.2.1-69057-14、7.2.2-72806-11はなく、それらの系列の最新ビルドは6.2.4-25556-8、7.1.1-42962-9、7.2.1-69057-13、7.2.2-72806-10であった（Rescanaによるアーカイブの解釈）。Synologyのプレスリリースは、「他のオペレーティングシステム、および一部のサポート終了DSMバージョン」向けの更新は「今後のリリースで予定されている」としている。DSM 6.2はアドバイザリの製品表には現れないが、説明中のそのビルドは、Synologyがそれを影響を受けるものとして扱っていることを示唆している（Rescanaの解釈）。

まだCVEレコードがない。 CVE.orgは、CVE-2026-120382について「The cve record for the cve id does not exist」と応答し、NVD APIは結果を返さなかった。これは11月20日の12:16 ESTと再度12:18 EST、および11月21日の15:41 ESTと再度15:44 ESTのことである。レコードが現れるまで、スコアと影響を受けるバージョンについてはSynologyのアドバイザリが唯一の情報源であり、NVDデータに依存するスキャナーはまだこの脆弱性を検出しない可能性がある（Rescanaの解釈）。

Synology製品におけるCVE-2026-123007。 SA-26:20は、NGINXの脆弱性に関するF5の説明を繰り返している。NGINXが細工されたHTTP/2トラフィックを処理するとき、「フロー制御ウィンドウが許容しきい値を超える可能性があり、ヒープバッファオーバーフローを引き起こし、通常はその後にNGINXワーカーのセグメンテーションフォールトが続く」とし、攻撃者は「アドレス空間配置のランダム化（ASLR）が無効化されているシステム、または攻撃者がASLRを回避できる場合に、コードを実行できる」としている。SynologyはCVE-2026-123007を「Important」とし、CVSS 3.1で8.1、ベクトル `CVSS:3.1/AV:N/AC:H/PR:N/UI:N/S:U/C:H/I:H/A:H` を付けており、これはCNAとしてのF5が付けた3.1のスコアと同じである。F5はCVSS 4.0でも9.2を付けている。SA-26:20の冒頭の概要は、SA-26:21と同じ「任意のファイルを読み取りまたは書き込み」という文言を使っている。F5のCVEレコードと一致する詳細セクションが、依拠すべき説明である（Rescanaの解釈）。Synologyのプレスリリースは「NGINX2Rootの脆弱性」と複数形で言及しているが、SA-26:20はCVE-2026-123007のみを挙げている。
