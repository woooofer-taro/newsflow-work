Barracudaのセキュリティアプライアンス、自身にセキュリティ上の問題を抱える

Barracuda’s security appliances have a security problem of their own
Network World2026-11-04 21:00報道

連鎖させると、認可バイパスとコマンドインジェクションの脆弱性により、攻撃者がBarracudaデバイスのroot権限を得る可能性がある。

幅広いサイバーセキュリティデバイスを提供するBarracudaが、自社でバグに見舞われた。

同社は、重大および高深刻度の2件の脆弱性を公表した。これらを連鎖させると、脅威アクターが認可制御を回避し、デバイスのroot権限を取得できる可能性がある。

これらは、CVE-2026-116606として追跡されている認証前の認可バイパスの脆弱性（共通脆弱性評価システムで重大の9.3と評価）と、CVE-2026-111560として追跡されているコマンドインジェクションの脆弱性（CVSSで高深刻度の8.6と評価）である。これらの脆弱性の悪用に成功するには、攻撃者は脆弱なデバイスの管理インターフェースにアクセスできる必要がある。

Barracudaはセキュリティパッチをリリースしており、顧客に直ちに適用するよう勧告している。

この脆弱性は多数の人気のあるBarracuda製品に影響する

メールゲートウェイでroot権限を得ると、攻撃者は、すべての受信・送信メッセージが通過する場所に位置することになる、とDickson ResearchのFrank Dickson氏は述べた。また、ゲートウェイがメールサーバーやディレクトリに接続するために使用する認証情報や接続も露出する可能性がある。「それらはいわば王国の鍵だ」と同氏は述べた。

CVE-2026-116606とCVE-2026-111560はどちらもBarracudaのEmail Security Gateway（ESG）に影響するが、CVE-2026-111560はWeb Security Gateway（WSG）、Web Application Firewall（WAF）、WAF Control Center（WCC）、Load Balancer Application Delivery Controller（ADC）、Message Archiver（BMA）にも影響すると同社は述べた。

これらの製品を使用している顧客は、システムが最新のファームウェアバージョンで動作しており、すべてのセキュリティパッチを受け取っていることを確認するべきだと同社は助言した。デバイスには利用可能な最新のファームウェアバージョンが表示される。デバイスのファームウェアが複数バージョン古い場合、ユーザーは複数回の更新を行う必要がある場合がある。

アプライアンスの管理インターフェースがウェブから公開アクセスできない企業は、露出がより少ないとBarracudaは述べた。同社は、これらのインターフェースへのアクセスを信頼できる内部ネットワークに制限し、露出を抑えるために適切なネットワークアクセス制御を適用するよう助言した。

「最大の懸念は、この2つの脆弱性がどのように連鎖しうるかだ」とInfotechのプリンシパル・アドバイザリー・ディレクターであるJon Nelson氏は述べ、認証をバイパスしてからコマンドインジェクションを悪用できる攻撃者は、露出したアプライアンスへのアクセスから、そこでのコマンド実行へと進めると指摘した。「それぞれの脆弱性を単独で評価すると、リスクを過小評価しかねない」と同氏は述べた。

Dickson氏は、セキュリティリーダーはアドバイザリーを注意深く読むべきだと付け加えた。アドバイザリーは一方の欠陥を「認証前」と呼びながら、「Authentication Required: Yes, administrative access」と記載しているためである。

「通常の意味では、両方が真であることはありえない」と同氏は指摘した。ここでのアクセスとは、おそらくパスワードなしでネットワーク経由で管理インターフェースに到達できることを意味する。

「管理インターフェースがインターネットに面しているなら、その条件はすでに満たされている」とDickson氏は述べた。

また同氏は、アドバイザリーが9.3の深刻度評価を「high」と表示しているが、標準的な尺度では9.0以上は実際には「critical」であると指摘した。「これらは小さなことだが、ラベルがパッチ適用の優先順位を左右する」と同氏は述べた。さらに、アドバイザリーはこれらの欠陥が現在悪用されているかどうかを述べていないが、悪用されていないとも述べていない。

企業はどう対応すべきか

「管理インターフェースをインターネットから切り離せ」とDickson氏は強調し、サイバーセキュリティコンサルタントとして、そのアドバイスを週に少なくとも数回は行っていると述べた。「エッジデバイスの管理インターフェースは、継続的に脆弱性の原因となっている。」

チームが管理アクセスを信頼できる内部ネットワークまたは専用の管理ネットワークに制限したら、「パッチが適切にインストールされたと思い込まず、パッチを検証する」べきだとDickson氏は助言した。そこから、管理ログを確認して不正な訪問者がいないか分析し、見慣れないアカウントがないか確認し、デバイスからの予期しない外向きの接続を探すべきだと同氏は述べた。

ここでは歴史が重要だと同氏は付け加えた。2023年、この同じEmail Security Gateway（ESG）でゼロデイが見つかった後、Barracudaは、侵害されたアプライアンスを持つ顧客に対し、パッチに頼るのではなく、完全に交換するよう伝えた。同氏の言葉では、「パッチは鍵を直す。だが、すでに誰が鍵を持っているかは教えてくれない。」

Nelson氏は、企業は誰が管理インターフェースに到達できるかを注意深く調べるべきだという点に同意した。さらに、適切に構成されたゼロトラストアクセス層などの追加の制御の背後にアクセスを置くべきである。

「それらのインターフェースをインターネットに直接公開することは、常に悪い考えだった」と同氏は述べた。「AIによって弱点の発見や攻撃の連鎖が容易になるにつれ、その露出はますます正当化しにくくなっている。」AIはまた、アプリケーションに本来の制御を回避させることができるビジネスロジックの弱点のような問題にまで、ソフトウェアの欠陥の探索を広げている。そうした文脈では、認証および認可のバイパスに特に注意を払う価値があるとNelson氏は述べた。

より多くのベンダーが高度なAIを使ってコードを調べるようになるにつれ、CISOは、より多くの欠陥の公表と、それらに対応するための期間がおそらく短くなることに備えるべきだと同氏は指摘した。「つまり、露出しているアプライアンスを特定し、アクセスを制限し、次のゼロデイが到来する前に対応計画を用意しておくということだ」と同氏は述べた。

各アプライアンスが何を露出させるかを理解する

セキュリティアプライアンスは企業ネットワークにおける脆弱性をますます生み出しており、それがサイバーセキュリティの議論を変えつつある。企業はネットワークを守るためにそれらに頼っているが、結局のところ、それらは自らの脆弱性を持つソフトウェアシステムである。

「それらは、攻撃者がまさにいたい場所に位置している」とDickson氏は述べた。

ファイアウォール、VPN、メールゲートウェイは設計上インターネットに面しており、それが彼らの仕事だと同氏は述べた。それらは機密性の高いトラフィックを目にし、認証情報を保持している。ほとんどはノートPCやサーバーを守るエンドポイント検知ツールを実行できないため、侵害が長期間検知されないままになりうる。また、すべての顧客が同じファームウェアを実行しているため、1つの有効なエクスプロイトが数千の組織に拡大しうる。

「議論は、どの箱を買うかから、その箱自体が何を露出させるかへと移りつつある」とDickson氏は述べた。「アプライアンスの購入はすべて、ネットワークで最も露出した地点でベンダーのコードを信頼するという判断だ。」それは企業内の他のあらゆる判断と同じ精査に値すると同氏は述べた。

購入者はベンダーに4つの質問をするべきだと同氏は助言した。管理インターフェースはデフォルトでインターネットに公開されているか、パッチはどれだけ早く提供されるか、自動的に適用されるか、ユーザーはどのようなログを見られるか、である。

「セキュリティアプライアンスは境界を守るだけではない」とDickson氏は指摘した。「それが境界そのものであり、組織が所有する最も攻撃されるシステムとして扱われるべきだ。実際にそうなのだから。」
