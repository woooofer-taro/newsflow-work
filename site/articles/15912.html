Cisco Expresswayの脆弱性、企業ネットワークへの侵入に悪用される事態に

Cisco Expressway flaw now used to hack company networks
2-Spyware2026-11-23 07:00報道

Cisco Expressway の欠陥、企業ネットワークへの侵入に使われる - 2-Spyware

ハッカーが、多くの企業がビデオ通話の運用や電話システムの接続に使っている Cisco 製品に侵入している。その手口は、Cisco が数週間前に修正した欠陥である。セキュリティ企業 F6 は、攻撃者がロシアの組織にあるインターネットに面した Cisco Expressway デバイス2台の完全な root 制御を奪い、その後ネットワーク内部の2台にも到達したと報告している。[1] 自社または IT プロバイダが Expressway をクラスタで運用していて、まだアップグレードしていない場合は、これを緊急の問題として扱うべきである。

Cisco Expressway デバイスに何が起きたか

この欠陥は CVE-2026-76466 として追跡されており、深刻度スコアは10点満点中9.8である。Cisco は2026年10月21日にアドバイザリを公開し、その時点では公開された発表や悪意ある使用は把握していないと述べた。[2] TechBytes の報告によると、その後、独立した研究者が動作するプルーフ・オブ・コンセプトのエクスプロイトを GitHub に投稿し、F6 は実際の攻撃がほぼ直後に続いたと述べている。[3]

The Hacker News は11月20日、侵入者がまずインターネットに面した Expressway マシン2台を侵害したと報じた。その後、内部ネットワーク上のさらに2つのクラスタノードに移り、合計4台のデバイスとなった。[1] F6 は、この攻撃を既知のいかなるハッキンググループとも結び付けていない。

この欠陥で攻撃者にできること

Cisco によると、ログインを持たず、デバイスへのネットワークアクセスだけを持つ攻撃者が、root と呼ばれる最高レベルの権限で任意のコマンドを実行できる。[2] 根本原因は Expressway クラスタ同士の通信の仕方にある。Cisco は、永続的な Cookie の使用と、TLS Verify Mode というクラスタリング設定が有効な場合にクライアント証明書の検査が欠けていることを原因としている。[1][2]

平易に言えば、正しい Cookie を持つ見知らぬ者が、デバイスのデータベースサービスに到達し、命令を送ることができる。Cisco は回避策はないと述べており、実質的な対処はソフトウェアのアップグレードだけである。[2]

影響を受ける対象

Expressway-C (Core) と Expressway-E (Edge) の両方が、仮想マシンとして動作しているか物理アプライアンスとして動作しているかを問わず影響を受ける。古いリリースを実行し、かつクラスタとして構成されている場合にのみ脆弱である。[2] 報告によると、単独で動作する Expressway 1台は、この特定の欠陥の影響を受けない。[3]

脆弱なリリースは X15.5.3 以前であり、X15.5.20 に移行すべきである。X14 以前を使用している場合は、単にパッチを適用することはできず、サポートされているリリースに移行しなければならない。[1][2] 家庭でこれを運用している人はほとんどいないが、小規模な会社の IT を管理しているなら重要である。

侵入後に攻撃者が行ったこと

F6 は、周到な侵入だったと述べている。root を取得した後、侵入者はクラスタメンバー間の信頼関係を利用して内部マシンへ移り、4つのノードすべてで管理者アクセスを得た。[3] 彼らは独自の Python スクリプトを実行してネットワークをマッピングし、SMB で共有フォルダを開き、Microsoft SQL Server と WinRM に接続し、内部の GitLab リポジトリから認証情報を引き出した。[1][3]

F6 は、スクリプト内に AI アシスタントがその改良を手伝ったことをうかがわせるコメントや変更説明を見つけており、攻撃者は作戦の実行中にツールを変更していた。[1][3] F6 は「境界デバイスの侵害は、攻撃者が組織の重要なシステムへ至る道を開く可能性がある」と警告した。[1] ランサムウェアの攻撃集団はこうした足掛かりを好む。これについては Akira ランサムウェアに関する当サイトのガイドで説明している。

Cisco と研究者の主張

Cisco は、この欠陥を報告した人物として Jane Street の Stefan Aleksic の名を挙げている。[2] 同社はアドバイザリで、問題は永続的な Cookie の使用によるものだと述べた。[1] TechBytes の報告は、Cisco のアドバイザリが更新されておらず、依然として悪意ある使用は把握していないと記載していたと指摘しており、したがって悪用の主張は現在、Cisco の確認ではなく F6 の調査に基づいている。[3]

今すぐ行うべきこと

Expressway を管理している場合は、まず X15.5.20 以降のサポートされているリリースにアップグレードすること。今日それができない場合、F6 は、外部ファイアウォールで着信 TCP ポート 4371 と 4372 をブロックし、自組織のクラスタメンバーの検証済みアドレスのみを許可するよう勧めている。[3]

  1. Expressway ノードがクラスタ化されているか、またどのリリースを実行しているかを確認する。
  2. X15.5.20 以降にアップグレードするか、X14 以前から移行する。
  3. それまでは、ポート 4371 と 4372 を既知のクラスタアドレスに制限する。
  4. Erlang ログ erlang.log で、F6 が侵害の兆候として挙げているエントリ wombat@127.0.0.1 を検索する。
  5. /mnt/harddisk フォルダ内の不審な Python スクリプトと、F6 が公開した2つのアドレス 66.179.31.32 および 18.130.47.116 への接続を探す。
  6. 侵入の兆候が見つかった場合は、デバイスを隔離し、接続されているシステムに保存されている認証情報を変更し、攻撃者がどこまで到達したかを突き止める。

WinRM はここで使われたツールの1つであり、winrmsrv.exe に関する当サイトのページは、偽のファイルがどのように Microsoft らしい外観を借りうるかを示している。Windows PC でのログの読み方については、HijackThis ログのガイドを参照のこと。

今後の展開

公開されたエクスプロイトコードは通常、より多くの攻撃者が同じ手口を試すことを意味するため、公開されている Expressway クラスタへのスキャンは続くと予想される。Apple の緊急 CoreAudio パッチに関する当サイトの報告にあるバグと同様に、修正から攻撃までの間隔は縮まり続けている。

管理者でない場合は、雇用主または IT プロバイダに、Expressway を使用しているか、そしてアップグレードしたかを尋ねること。

よくある質問

CVE-2026-76466 とは何か？

Cisco Expressway の深刻な欠陥で、スコアは10点満点中9.8であり、認証されていない攻撃者がクラスタ化されたデバイス上で root としてコマンドを実行できる。

Cisco は修正したか？

はい。Cisco は2026年10月21日に Expressway X15.5.20 で修正をリリースした。X14 以前の古いリリースは、サポートされているバージョンに移行しなければならない。

パッチを適用できない場合の回避策はあるか？

Cisco は回避策を挙げていない。F6 は、外部からの着信 TCP ポート 4371 と 4372 をブロックし、信頼できるクラスタメンバーのアドレスのみを許可することを提案している。

誰が攻撃されたか？

F6 はロシアの組織での侵入を調査しており、そこでは攻撃者が4台の Expressway デバイスを侵害した。この攻撃は既知のいかなるグループとも結び付けられていない。

自宅でビデオ通話を使っている場合、これは自分に影響するか？

Expressway は企業向け機器であるため、おそらく直接は影響しない。雇用主や IT プロバイダが使用している可能性があるので、尋ねてみる価値がある。

Cisco は攻撃を確認しているか？

私たちが読んだ資料には確認はない。TechBytes の報告は、Cisco のアドバイザリが依然として既知の悪意ある使用はないと述べていたとしており、したがってこの主張は F6 の調査結果に基づいている。
