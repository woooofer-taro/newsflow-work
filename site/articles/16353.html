Linux NFSファイル共有の欠陥によりサーバーがリモートで乗っ取られる恐れ

Flaw in Linux NFS file sharing exposes servers to remote takeover
Network World2026-11-28 07:00報道

脆弱性は12年間Linuxカーネルで検出されず、サーバーのファイル共有ポートに到達できる者なら誰でも、パスワードなしでroot権限を取得できる。

研究者らは、Linuxカーネルの NFS ファイル共有サーバーに重大な欠陥を発見した。この欠陥により、認証されていない攻撃者が影響を受けるシステム上でrootシェルを取得できる。この欠陥は12年間カーネル内で検出されないままだったが、2人の研究者が、うち1人はAIエージェントを使って、それぞれ独立に発見した。

NFS は通常、Kubernetes クラスターのコンテナネットワークや開発環境のビルドサーバーを含む、ローカルネットワーク内で使用される。しかし、多くの組み込みデバイスやネットワーク接続ストレージ（NAS）デバイスでも有効になっており、これらは古いカーネルバージョンを実行している可能性があり、ファームウェア更新によってのみパッチを適用できる。

CVE-2026-99362 として追跡され、NFS2ROOT と名付けられたこの欠陥は、多くの Linux ディストリビューションでデフォルトとなっている Network File System プロトコルの NFSv4.1 または NFSv4.2 バージョンを実行するシステムに影響する。この脆弱性により、サーバーのポート 2049 に到達できる者なら誰でも、NFS リクエストを処理するカーネルコンポーネントである *nfsd* プロセスのメモリを破壊できる。深刻度は 9.8 と評価されている。

フランスのセキュリティ機関 ANSSI の研究者 Jérémy Jean が8月にこのバグを発見し、その修正は9月14日にメインラインカーネルにマージされた。

このヒープオーバーフロー脆弱性も発見し、今週その技術的詳細を公開したセキュリティ企業 OpenSec Intelligence によれば、この欠陥はroot権限のシェルを取得するために悪用され得る。OpenSec は、AI を活用したセキュリティテストハーネスを使ってこのバグを発見し、9月22日に独自のパッチを Linux カーネルのメンテナーに提出した。

しかし、サポートされているすべてのカーネルブランチが修正をバックポートするには時間がかかるため、このバグは11月19日まで公開されず、CVE ID も割り当てられなかった。

この欠陥は2014年に Linux 3.16 で導入され、現在は8つの安定版カーネルブランチでパッチが適用されている: 5.10.275、5.15.226、6.1.193、6.6.163、6.12.117、6.18.61、7.3.2、および 7.4-rc1。

すぐにパッチを適用できないシステムでは、管理者は信頼できないシステムからのポート 2049 へのアクセスをブロックするファイアウォールルールを使用することが推奨される。別の選択肢として、*nfsd* の設定で NFSv4.1 と 4.2 を無効にしてからサービスを再起動する方法があるが、これにより pNFS といくつかの機能が無効になる。
