Cisco Expresswayの脆弱性が悪用され内部ネットワークが侵害される (CVE-2026-76466)

Cisco Expressway vulnerability exploited to breach internal networks (CVE-2026-76466)
Help Net Security2026-11-24 07:00報道

Cisco Expressway の脆弱性が悪用され、内部ネットワークが侵害される（CVE-2026-76466）

ロシアのセキュリティ企業 F6 は先週末、攻撃者が Cisco Expressway ゲートウェイの重大な脆弱性（CVE-2026-76466）を悪用して組織に侵入しているのが確認されたと明らかにした。

米国のサイバーセキュリティ・インフラストラクチャセキュリティ庁は金曜日、この脆弱性を Known Exploited Vulnerabilities カタログに追加した。同時に追加されたのは CVE-2026-123890 で、これは VMware vCenter の認証バイパスの脆弱性であり、中国と関係があると疑われるスパイ活動グループによって数か月間ゼロデイとして悪用されてきた。

CVE-2026-76466 について

脆弱な Cisco Expressway デバイスへネットワークアクセスできる、認証されていないリモートの攻撃者は、CVE-2026-76466 を使って *root* として OS コマンドを実行できる。

CVE-2026-76466 は Cisco Expressway Core（Expressway-C）および Cisco Expressway Edge（Expressway-E）デバイスに影響する。これらのデバイスは、リモートワーカーや外部パートナーに、VPN なしで社内の音声・ビデオ・メッセージングシステムへの安全なアクセスを提供するため、また、オンプレミスのコラボレーション基盤を Cisco Webex クラウドに接続するために、組織で使用されている。

この欠陥はクラスター構成の展開のみに影響すると Cisco は説明した。この欠陥は Expressway のクラスターピアが使用するデータベースサービスにある。このサービスは永続的な Cookie に依存しており、クラスター TLS 検証モードが有効な場合でもクライアント証明書が検証されない。

実環境での悪用

F6 によると、攻撃者は最初にインターネットに面した境界デバイス 2 台を侵害しており、それらはおそらく Expressway Edge デバイスだった。攻撃者はそのうち 1 台を足がかりとして、組織の内部ネットワーク上にある追加のクラスターノード 2 台へアクセスした。

「root アクセスを取得した後、攻撃者はインフラ全体でさらに横展開するためのツールの準備を始めた。攻撃者は、ネットワークをスキャンし、アクセス可能な SMB リソースを発見し、SQL Server および WinRM と連携し、認証情報やその他の機密情報を窃取するために GitLab リポジトリを探索するよう設計されたカスタム Python スクリプトを使用した」と同社は明らかにした。

何をすべきか

F6 は、攻撃に使われた IP アドレス（66.179.31[.]32 および 18.130.47[.]116）、Python スクリプトが配置されたパス（/mnt/harddisk/i{0-9}{4}[a-zA-Z]?/*.py）、および悪用された Cisco Expressway デバイスの Erlang システムログに現れる特定のエントリ（nodeup ‘wombat@127.0.0.1’）を共有した。

上記のログエントリが検出された場合、組織は他のログを確認し、Python スクリプトを探して、侵害を確認すべきである。

顧客は Cisco Expressway をリリース X15.5.20 以降に更新するよう勧告されている。「直ちに更新できない場合、F6 は、ファイアウォールで TCP/4371～4372 ポートへの接続を制限し、信頼できるクラスターノードの IP アドレスからのアクセスのみを許可することを推奨する」と F6 は助言した。

「このインシデントは、境界デバイスの侵害が、攻撃者が組織の重要なシステムへ到達する経路を開き得ることを示している。つまり、防御には、適時の脆弱性修正だけでなく、適切に構成されたセグメンテーションとインフラ監視も含めるべきである」と同社は付け加えた。
