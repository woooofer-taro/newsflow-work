Cisco、Sydney の Cloud Control インスタンスを2月に開始する目標

Cisco targets February launch for Sydney Cloud Control instance
iTWire2026-11-10 21:00報道

Cisco、シドニーのCloud Controlインスタンスを2月に立ち上げる目標 - iTWire

Ciscoの地域責任者によると、計画中のオーストラリアのインスタンスはシドニーに展開され、このプラットフォームは人間のオペレーター、エージェント、インフラストラクチャを共有の運用環境に集約する。

Cisco Cloud Controlは、すべてのCiscoデバイスと情報を1か所に集約する、まったく新しい統合ポータルだ。確かにそのとおりだが、それでは全体像を描けていない。実際のところ、Cisco Cloud Controlは機器群の「単なる」コントロールパネルよりもはるかに興味深い。すべてのテレメトリ、インベントリ、トポロジーなどをまとめ、Ciscoインフラストラクチャ全体を単一のビューで提供する。さらに、問題のトラブルシューティングと修復をより速く行うためのAIツールが組み込まれ、他の人と作業するための共有キャンバスや、その他多数の機能が組み合わさり、ネットワーク管理者が常駐する場所として非常に魅力的なものになっている。

Cisco Cloud Controlはすでに米国で稼働しており、Ciscoはオーストラリアでの提供開始を2027年2月に目指していると発表した。地域責任者のStefan Leitlは、計画中のオーストラリアのインスタンスの場所としてシドニーを挙げた。

メルボルンで開催されたCisco Liveで講演したポートフォリオ戦略・マーケティング担当シニアバイスプレジデントのJeff Schultz（写真）は、オーストラリアはこの展開で欧州連合および英国に加わり、日本、インド、カナダが5月に続くと述べた。このプラットフォームは米国ではすでに一般提供されている。

Leitlは*iTWire*に対し、Ciscoはユースケースとオンボーディングについて5〜6社のベータ顧客と協力していると説明した。同氏は、意図されているオーストラリアでの提供は、プラットフォームの既存の機能を提供し、時間をかけてさらなる革新が追加されると述べた。Leitlは、計画中のシドニーでの展開はソブリンインスタンスになると述べた。

人とエージェントのための共通環境

Schultzは、人々が定期的にチャットボットに質問する状態から、エージェントが継続的に働き、ツールを呼び出し、他のエージェントと連携する状態への移行について説明した。これは、活動量とそれに伴う責任の両方を変える。

実際、Ciscoはエージェンティック AIが現実のものとなって以来のネットワークデータの大きな変化の説明にしばらく時間を割いた。そして、世界中で何百万台ものCiscoデバイスが使用されており、Ciscoはネットワークトラフィックについて、他にほとんど共有できない独自の高レベルな視点を間違いなく持っている。

Schultzは、この変化を示すOpenRouterのデータを指摘した。9月の最終週、エージェンティックに分類されたAPIキーは、このサービスで人間に分類されたキーが使用したトークンの約7倍を占めた。Schultzは、エージェントは立ち止まって考えたり、トイレに行ったり、昼食をとったり、帰宅したりする必要がないと説明した。彼らは24時間365日働く。さらに同氏は、エージェントでは*ノース・サウス*トラフィックが増えること――インターネットなどに出てドキュメントを見たり、MCPやAPIなどとやり取りしたりする――と、*イースト・ウェスト*トラフィックが増えること――組織内の他のラック上やサーバー上の他のエージェントと並んで作業するため――を説明した。

つまり、エージェンティック AIはネットワークトラフィックの爆発的な増加をもたらしている。そして、困り果てた人間はそれをどう管理するのか。そこで登場するのがCloud Controlだ。

Cloud Controlは、インベントリ、トポロジー、アラート、アイデンティティ、ワークフローを共有の運用環境に集約する。Cisco AI Assistantは自然言語の入り口を提供し、AI Canvasはチームとエージェントが一緒に問題を調査するための永続的なワークスペースを提供する。専門のプロダクトコントローラーは引き続き管理と実行の責任を保持するが、Cloud Controlは既存のダッシュボードを補完し、機能は接続された製品、権限、サブスクリプションに基づく。

6月に導入されたプラットフォームの上に構築

Cloud Controlは2026年6月のCisco Live USで発表され、8月25日に米国で一般提供となった。今週のメルボルンの基調講演は、地域ごとのスケジュールとCiscoの方向性のより詳しい説明とともに、このプラットフォームをオーストラリアでの議論に持ち込んだ。

同じく6月に発表されたCloud Control Studioにより、顧客とパートナーは自らの運用要件に合わせたカスタムアプリとエージェントを構築できる。その役割は、共有環境を各組織に固有のワークフロー、システム、専門知識にまで拡張することだ。

Schultzはまた、Cloud Controlのサポートは将来のCisco製品の要件になると述べ、このプラットフォームが同社の製品戦略においていかに中心的になったかを強調した。

Cisco Model Foundryは、カスタマイズをさらに拡張する。10月のPartner Summitで限定提供として導入され、パートナーが最初にアクセスできる。Ciscoの専門モデルと、顧客データを使ったオプションのファインチューニングへのアクセスを提供する。

パートナーはこの機能をネットワーク構成、ログ、トラブルシューティング履歴に適用し、その後、適応させたモデルが顧客のタスクでより高い性能を発揮するかを評価できる。Schultzは、一般提供をロードマップ上の2027年6月に置いた。

より少ない導入作業で、より有用なシグナルを

この戦略は、顧客の労力を減らしながら有用な情報をシステムに取り込むことにも依存している。ThousandEyesはその一例だ。

Ciscoは、Wi-Fi 6EおよびWi-Fi 7アクセスポイントにネイティブのThousandEyesインテリジェンスを搭載し、対象となるCisco Networking EssentialsおよびAdvantageライセンスに含まれると発表した。この統合は、エージェントのプロビジョニング、関連サービスの検出、合成テストの展開を自動的に行うことを意図している。

これらのテストは、ユーザーがオフラインのときを含め、アプリケーションとネットワークのパフォーマンスの背景的な証拠を提供する。基調講演でSchultzは、簡素化されたライセンスと導入の機能は2026年12月の一般提供を目標にしていると述べた。

それは事実だが、別のマイルストーンはすでに到来している。Ciscoは11月9日、有線および無線クライアントエクスペリエンス向けのExperience MetricsがMeraki Dashboardで一般提供になったと発表した。

この機能は、チームが影響を受けているクライアントと劣化の可能性の高い原因を特定するのに役立ち、利用可能な詳細はプラットフォーム、ファームウェア、テレメトリによって異なる。個々のネットワークコンポーネントの状態に加えて、人々が受けるエクスペリエンスに応じて調査の優先順位を付ける方法を提供する。

制御は能力に追随しなければならない

この運用モデルは、Ciscoのより広い戦略においてAI DefenseとSplunkが重視される理由も説明している。エージェントがどのように失敗しうるかをテストし、その挙動を観察し、活動をコストと成果に関連付けることは、エージェントの権限が大きくなるにつれてますます重要になる。

エージェントは問題の特定から始まり、変更の推奨へと進み、最終的には承認されたアクションを実行するかもしれない。各段階で、組織はどのような証拠、権限、監督が適切かを決める必要がある。

オーストラリアの顧客にとって、2月という目標と計画中のシドニーインスタンスは、展開により具体的な形を与える。実務上の問いは、どのワークフローが現地で利用可能になるか、そのデータがどのように扱われるか、そして顧客が自分たちに代わって動くエージェントをどのように統制できるかである。

もちろん、もう一つの重要な問いは、自分に代わって作業を行うエージェントをどの程度信頼するかである。これについて、Ciscoには語るべきことがはるかに――*はるかに*――多い。それは記事一本分に相当するほどであり、Ciscoが信頼と確信を確保するために何をしているかの詳細、およびCisco Live Melbourne 2027からのさらなるニュースについては、*iTWire*にご注目いただきたい。
