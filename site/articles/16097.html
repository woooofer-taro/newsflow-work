攻撃者がAzure API Managementの欠陥を悪用して機密情報を盗んだとMicrosoftが警告

Attackers exploited an Azure API Management flaw to steal secrets, Microsoft warns
Network World2026-11-25 07:00報道

攻撃者がAzure API Managementの欠陥を悪用してシークレットを窃取、とMicrosoftが警告

ノルウェーの治安機関は、この欠陥をエネルギー企業2社への攻撃と結び付け、すべての顧客に対し、シークレットが漏洩したものと想定するよう伝えている。

Microsoftは、攻撃者がAzure API Management Classic tiersの欠陥を悪用して保存されたシークレットを窃取したとして、顧客に警告している。この侵入について、ノルウェー国家安全保障局は2社のエネルギー企業での侵害と結び付けており、漏洩した認証情報は侵害されたものと各組織は想定すべきだとしている。

Microsoftは、顧客に送ったAzure Service Healthのセキュリティアドバイザリーの中で、11月18日にこの脆弱性を特定し、翌日に緩和策を展開したと述べた。追跡IDがMZK9-GH0のこのアドバイザリーは、Microsoftが欠陥を発見する前から露出が始まっていたとしている、とBleeping Computerは報じた。

同社はアドバイザリーの中で、「権限のない第三者がこの問題を利用して、Azure API Management Classicインスタンスに保存されたシークレットにアクセスできた可能性がある」と述べた。

漏洩した可能性のある情報には、Named Valuesに保存されたシークレット、IDプロバイダーおよびOpenID Connectプロバイダーに関連付けられたクライアントシークレット、サブスクリプションキー、直接管理APIの呼び出しに使われるトークンが含まれる、と同報道は付け加えた。

Microsoftは、同社の緩和策は、すでに侵害された認証情報を無効にするものではなく、影響を受けた顧客は漏洩した可能性のあるシークレットをローテーションし、不審なアクティビティを調査しなければならないと警告した。アドバイザリーによれば、影響を受けるのはサービスのClassic tiersのみで、Azure API Management v2は影響を受けない、と同報道は付け加えた。

この潜在的な露出は、理論上のセキュリティリスクにとどまらなかった。ノルウェー国家安全保障局（NSM）はその後、エネルギー企業2社へのサイバー攻撃をこの脆弱性と結び付け、運用環境での悪用の証拠を示した。

ノルウェー、顧客に漏洩を想定するよう通告

11月20日に公開され11月23日に更新されたセキュリティアドバイザリーで、NSMは、身元不明のアクターがAzure API Managementに保存されたアクセストークン、シークレット、Named Valuesを積極的に標的にしていたと述べた。

NSMはアドバイザリーの中で、「今週初め、NSMは、複数のノルウェー企業に影響を及ぼすAzure API Management（APIM）の脆弱性を把握した」と述べた（ノルウェー語からの翻訳）。

NSMは、この脆弱性は現在は塞がれているはずだが、それでも各組織に対策を講じるよう求めたと述べた。

アドバイザリーは、「Azure API Managerを使用している者は誰でも、自分たちのシークレットとNamed Valuesが漏れているものと想定しなければならない」と付け加えた。「これは、事業者がすべてのトークンとシークレットをロールバックしなければならないことを意味する。」

アドバイザリーの中で、NSMの運用サイバーセキュリティ担当ディレクターのMartin Albert-Hoffは、この脆弱性は最初にノルウェーのエネルギー部門によって発見されたと述べた。同機関は、影響を受けた組織の中にEquinorとSkagerak Energiを挙げ、この脆弱性は他の国や部門の組織にも影響を及ぼしたと述べた。

Equinorは、11月17日に一部のITシステムに対するサイバー攻撃を公表した。11月20日に公開した更新情報で、同社は、攻撃は止められ、生産は通常どおり行われており、データが盗まれたり改ざんされたりした兆候はないと述べた。

その翌日、Skagerak Energiは、一部のITシステムに対するサイバー攻撃未遂を報告した。同社は、この事案は事業運営や生産に影響を与えておらず、情報が侵害された兆候はないと述べた。

NSMは、脆弱性の公開が、さらに多くの脅威アクターに悪用を試みるよう促す可能性があると警告した。

同機関はアドバイザリーの中で（ノルウェー語からの翻訳）、「脆弱性が知られるようになると、複数のアクターが悪用を試みる可能性がある」と述べ、人工知能の利用が急速に拡大していることが脅威環境に影響していると付け加えた。

MicrosoftのアドバイザリーにもNSMの通知にも、この欠陥のCVE識別子は含まれていない。

認証情報をローテーションする緊急の必要性

Microsoftの緩和策は、管理プレーンへの不正アクセス経路を塞いだが、顧客に対し、修正前にAPIMインスタンスにアクセスされたかどうか、保存された認証情報が漏洩した可能性があるかどうかを調査するよう助言した、と同報道は付け加えた。

Microsoftは、Azure Integration Servicesブログの11月21日付の投稿で、Azure API Managementに構成された認証情報を特定してローテーションするためのガイダンスを公開した。

このガイダンスは、サブスクリプションキー、シークレットを含むNamed Values、バックエンド認証情報、OAuth 2.0およびOpenID Connectのクライアントシークレット、接続文字列、およびAPIポリシーに直接書き込まれた認証情報を対象としている。

Microsoftは、各組織に対し、認証情報をAPIM内で値を更新するだけにとどめず、それらが最初に発行されたシステムでローテーションするよう推奨した。

同社はブログ投稿で、「API Managementで値を更新するだけでは、古い認証情報は無効にならない」と述べた、と同報道は伝えている。

NSMは、より広範な推奨事項を出しており、Azure API Managementを使用する組織に対し、シークレットとNamed Valuesが漏洩した可能性があると想定し、関連するすべてのトークンとシークレットをローテーションするよう助言している。

同機関はパッチ確認方法も公開した。NSMによれば、0.52.xブランチのインスタンスはビルド31936から、0.53.xのインスタンスはビルド31938からパッチが適用されている。V2およびConsumption tierのインスタンスは脆弱ではないと同機関は述べた。

アドバイザリーによれば、パッチが適用されていないインスタンスを持つ組織はMicrosoftに直接連絡すべきであり、侵害の兆候を確認した組織はNSMに連絡すべきである。

アドバイザリーの公開後に検知およびハンティングのガイダンスを公開したクラウドセキュリティ研究者のAnders Kristiansenは、パッチを適用するだけでは十分ではないと述べた。

Kristiansenはブログ投稿で、「APIMを運用しているなら、パッチ適用で終わりではない」と書いた。

彼のローテーション対象リストには、バックエンド認証情報、アプリ登録のシークレット、サブスクリプションキー、サービスが参照するKey Vaultのシークレット、テナントアクセスキーが含まれる。Microsoftは、CSOのコメント要請にすぐには応じなかった。
