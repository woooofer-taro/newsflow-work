ハッカーがCisco Expresswayの重大な欠陥を悪用、4台のデバイスに侵入し内部ネットワークに到達

Hackers Exploit Critical Cisco Expressway Flaw, Breach Four Devices and Reach Internal Network
The Hacker News2026-11-21 07:00報道

脅威アクターが、Cisco Expressway で最近公開された重大なセキュリティ上の欠陥を悪用し、概念実証（PoC）エクスプロイトの公開から間もなくロシアの組織に侵入していることが確認された。

この活動には CVE-2026-76466（CVSS スコア: 9.8）の悪用が含まれる。これは、Cisco Expressway デバイスにネットワークアクセスできる、認証されていないリモートの攻撃者が、root として任意のオペレーティングシステムコマンドを実行できる可能性のある脆弱性である。

「この脆弱性は永続的な Cookie の使用に起因する」と Cisco は先月下旬に公開したアドバイザリで述べた。「さらに、クラスタリングで TLS Verify Mode が Enabled に設定されている場合、クライアント証明書の検証が不十分であり、クライアント証明書が検証されない」

「Cookie を所持する攻撃者は、データベースサービスに接続し、特定のリモートプロシージャコール（RPC）コマンドを呼び出すことで、この脆弱性を悪用できる可能性がある。悪用に成功すると、攻撃者は影響を受けるデバイスの基盤となるオペレーティングシステム上で root として任意のコマンドを実行できる可能性がある」

この欠陥に対するパッチは、2026年10月21日に以下のバージョンでリリースされた -

  • Cisco Expressway Series Release X14 以前 - 修正済みリリースへ移行
  • Cisco Expressway Series Release X15.5.3 以前 - X15.5.20

木曜日に公開されたレポートで、ロシアのサイバーセキュリティ企業 F6 は、PoC エクスプロイトが公開された後、この欠陥を悪用して、侵害された Cisco Expressway X15.5.3 デバイス上で root 権限によるリモートコマンド実行を得た、実環境での悪用の最初の事例とみられるものを確認したと述べた。

「攻撃者は当初、インターネットに面した 2 台の Cisco Expressway デバイスを侵害した」と F6 は述べた。「そのうちの 1 台を通じて、組織の内部ネットワーク上にある追加の 2 つのクラスタノードへのアクセスを得た」

root アクセスの取得後、攻撃者はネットワーク内で横展開を試み、カスタムの Python スクリプトを使用してネットワークをスキャンし、アクセス可能な SMB リソースを発見し、SQL Server および WinRM とやり取りし、認証情報やその他の機密データを外部に持ち出すために GitLab リポジトリにアクセスしたとされる。

スクリプトの分析は、コメントや修正の説明が存在することから、人工知能（AI）ツールの支援を受けて開発された可能性があることを示している。

同社は、この活動に関連する以下の侵害指標（IoC）を共有している -

  • 地理位置情報が特定された IP アドレス: 66.179.31[.]32 および 18.130.47[.]116
  • 影響を受けた Cisco Expressway デバイス上の Erlang システムログ（erlang.log）に "wombat@127.0.0.1" が存在すること
  • "/mnt/harddisk/i{0-9}{4}[a-zA-Z]?/*.py" に配置された Python スクリプト

この攻撃は、既知の脅威アクターやグループには帰属されていない。ユーザーは、Cisco Expressway のサポートされている最新バージョンに更新し、環境内の侵害の兆候を監査し、影響を受けたシステムを隔離し、攻撃の範囲を特定し、潜在的な横展開の経路を遮断することが推奨される。

「このインシデントは、境界デバイスの侵害が、攻撃者が組織の重要なシステムへ至る経路を開く可能性があることを示している」と F6 は述べた。「つまり、保護には、タイムリーな脆弱性の修正だけでなく、適切に構成されたセグメンテーションとインフラストラクチャの監視も含めるべきである」
